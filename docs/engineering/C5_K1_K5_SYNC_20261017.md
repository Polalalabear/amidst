On `target_reconstruction`, C4b verifies each original draft seal and current RGB/evaluation freshness, then reconverts feedback in request order against the baseline and earlier surviving feedback. Clients still submit only issued refs; they cannot supply frame keys or detector/visibility data.
- **Accept `invalid_applied_frame_keys` and reason `APPLIED_FRAME_KEY_MALFORMED` as additive conversion diagnostics.** It is surfaced in retrieval responses and sealed C4b `review_evidence.feedback_conversion`, and preserved in the new receipt. Normal backend keys come from the native helper, so the actual run returns `[]`. A nonempty list means malformed caller keys; it is not evidence that a frame was excluded. The pure converter's upstream behavior (report and drop malformed keys) is unchanged. Contract-owner follow-up: document this additive diagnostic and the four typed detector fields explicitly; no unilateral contract rewrite here.
- **Keep detectability_factor, required_px and min_predicted_px validation retrieval-side.** They verify the internally pinned C5 index's projection-area policy (finite positive factor, required_px = factor × min_pixels, admitted polygon minimum ≥ required_px). They are additional local index-integrity guards, not new K1/K5 prerequisites in contract §6.1. The backend gates both initial baseline and later evidence with these guards. Native K1 independently enforces the shared four-field detector equality and strict visibility rule. The pure module is not responsible for evaluating C5's index-generation policy. If a future producer needs shared area-policy validation, Claude should draft that separately; this sync does not expand §6.1.
- C7 `person` restricted-policy loader output is now passed directly as `restricted_layer` and its pinned SHA as `expected_restricted_sha256` on every K1 call, including reruns. Review status is `NATIVE_K1_LABELS_ONLY`; `configuration.restricted_ref`, provenance restricted hash, `checks.walkable.restricted_area_crossed` and per-region `restricted_policy_sample_indices` are emitted natively. This is a labels-only policy layer, not physical geometry or a ranking change.
