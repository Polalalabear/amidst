> 這邊描述到工作樹乾淨，目前情況不是避免使用工作樹嗎

**當時的回答**

> 兩個詞指的是不同的東西，沒有衝突：
>
> - **「不要建 worktree」**：指 `git worktree add` 這個功能，也就是用同一個 repo 另外開出第二份 checkout。專案規則禁止這樣做，所以合成副本都是在 scratchpad 用 `git clone --no-checkout` 另外複製一份，或用 `git archive` 匯出。
> - **「工作樹要乾淨」**：「工作樹」（working tree）是任何一份 checkout 裡實際展開的檔案。「乾淨」是指追蹤中的檔案沒有未提交的修改。啟動器會檢查這一點，有未提交的修改就拒絕啟動，以確保 Demo 跑的程式碼對得上某個 commit 的 hash。
>
> 所以 Codex 寫的彩排步驟是指：在合成副本（那份 clone）裡，解完衝突後要先 commit，讓那份副本的工作樹是乾淨的；另外要設 `OFFICE_ASSETS_REPO`，因為 clone 出來的副本找不到資產的位置。上次端到端驗收就是這樣做的，沒有用到 `git worktree`。
>
> 另外，共用 checkout 那 6 個未追蹤檔不影響這項檢查，因為它只看追蹤中的檔案；而且彩排是在副本上跑，不是在共用 checkout 上跑。
