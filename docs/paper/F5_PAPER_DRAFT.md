## 1. 引言

**問題。** 多鏡頭監視影像中，操作者要持續追一個人：目標走出鏡頭、被遮擋、或和別人交錯時，系統必須決定「還在不在、在哪個框、下一台看哪裡」。本文問：能看畫面、拿到鏡頭空間資訊的 Agent，能否取代以 RT-DETR 偵測、HSV 顏色與規則閘門組成的規則追蹤，在困難劇本上更少錯人？

**怎麼拆。** 假設分成六個（H1–H6，見 [`AGENT_VS_RULE_HYPOTHESES_20261120.md`](../evaluation/AGENT_VS_RULE_HYPOTHESES_20261120.md) §0.1）：H1 切換決策、H2 機制（好處是否來自看圖）、H3 閘門改成資訊、H4 空間資訊、H5 逐格辨識、H6 全模式可切換。本文報告三組實驗，每一組都在看結果之前先登記判定門檻：

1. **W1**（逐格辨識，H5）：r004 兩個簡單事件、422 格分層樣本。看圖 Agent 的整體 F1 高於規則（主準則 0.957 對 0.523，差 +0.433 [0.324, 0.566]；IoU 準則 0.887 對 0.518，沒有重算區間）。
2. **E3**（第 3 章）：Agent **依附**規則追蹤器（只能選規則本地軌跡上的人，答案透過規則追蹤器的有限介面生效），16 段困難劇本、68 個決策點。H1、H2、H4 **不成立**。
3. **E5**（第 4 章）：Agent **完全開放**：直接決定目標框與下一台鏡頭，判斷之間由不看顏色的中性追蹤器延續，只受資源限制。離線（AO，K=3）與模擬即時（AO-L，K=1，分開判定）兩種。H8a、H8b **不成立**，H8c **無法判斷**，H8d（K=1）**不成立**。

**結論的範圍。** 兩個實驗的結論都**只限於各自的整合設計與 E3 這 16 段合成劇本**：E3 是「依附規則」的整合，E5 是「這個 A-open 設計」（`gpt-6.1-terra`、每 2.0 s 定期提問、`E5_EXTRA` 提示、中性追蹤器、起點取自規則第一次 ACQUIRE）。本文不主張「Agent 普遍較差」或「較好」。W1 的辨識層優勢與 E3／E5 的決策層結果並列呈現，但兩者的資料不同（W1 是兩個簡單事件逐格離線；E3／E5 是 16 段困難劇本），不能直接相減。

**共同邊界。** 所有場景都是合成的（沒有真實監視影像），不能外推到真實影像；W1／W2 與 E3／E5 的畫面來源與管線不同，見第 2 章「資料來源」。身分一律 `UNCONFIRMED`：「對」只表示顯示的框或估計位置落在 GT 目標上，不是身分確認。GT、人物世界座標與軌跡、可見性、depth 只在評分端讀取，推論端不讀。可行走連通是圖上的宣告，實體導航與碰撞是 `UNKNOWN`。

## 2. 方法總覽

**系統。** 規則基線（B1）是現行 LIVE 路徑：RT-DETR（R18）偵測人物，HSV 顏色與規則閘門決定目標的框與重新取得，預設參數。看圖 Agent 是 `gpt-6.1-terra`（Responses API），經統一介面 `src/amidst/q1q5/agent_service.py`（`RULE`／`AGENT` 兩種模式；`RULE` 不呼叫模型）；無效回應或 ApiGuard 拒絕時退回規則並記 `fallback_reason`。Agent 模式依 D340：規則模式是預設與退路，Agent 可看渲染畫面、可選任何偵測或自畫框，每個請求帶場景資訊（`scene_context`：鏡頭圖、可行走連通、FOV、靜態門洞，不含牆面裁切，D348）；規則閘門只當資訊，Agent 推翻閘門記 `RULE_OVERRIDE`。

**實驗與預先登記。** 每個實驗在任何付費呼叫之前提交預先登記：判定規則、評分器（`e3_scoring.py`，SHA-256 `acacce396f27e0d7c8bf03d527b22272f2622376ed4a43ae6db0842353f87d08`）與結論用語。結論只用四種字眼：**成立、不成立、無法判斷、探索性**。統計方法：以段為單位的 cluster bootstrap（95% 百分位區間），決策點用 McNemar 檢定；段內的決策點與 tick 高度相關，所以區間以段為群集。

## 3. E3：依附規則的看圖 Agent 對規則

### 3.1 方法：Agent 的判斷依附在規則追蹤上

E3 比較規則與看圖 Agent 在困難劇本上的切換決策。這裡的 Agent **不是**獨立的追蹤器：它掛在規則的 LIVE 追蹤路徑上，只在特定時機被問，答案也只能透過規則追蹤器的有限介面生效。本章所有結論都限於這種「依附整合」。

**組別**（預先登記 §2）：

| 組 | 內容 | 空間資訊 | K |
|---|---|---|---|
| B1 | 規則：RT-DETR＋HSV＋規則閘門（現行 LIVE 路徑，預設參數） | 現行鏡頭鄰接 | 1 |
| B2 | B1＋改善的空間排序（只改「下一台看哪裡」的排序，其他不變） | F2 空間圖 | 1 |
| A1 | 看圖 Agent，請求不帶 `scene_context` | 無 | 3 |
| A2 | 看圖 Agent＋`scene_context`（D340：可選任何偵測、自畫框、答「不在，下一台看 X」） | 鏡頭圖、可行走連通、FOV、靜態門洞；**不含牆面裁切**（D348） | 3 |
| A3 | A2＋模擬即時：答案在實測延遲後才生效，以 IoU ≥ 0.3 逐 tick 串接，串不上記 `EXPIRED`（§7、D352） | 同 A2 | 3 |

A1 與 A2 的影像輸入完全相同，唯一差別是請求是否帶 `scene_context`；受測模型是 `gpt-6.1-terra`。F4 比對了 1535 個相同擷取時刻，影像 0 次不一致。

**Agent 何時被問、答案怎麼生效**（F4 報告 §1、§6）：Agent 在 LOST、AMBIGUOUS（4 m 內有兩人以上）、RECHECK（每 4 s）時被問；A2 共 1684 次，平均每段約 105 次。答案生效的方式：

- `SELECT`：只能選 1.5 s 內看過、而且沒有爭議的人，一次性重設規則追蹤器。
- `NOT_VISIBLE`：只解除鎖定。
- `OWN_BOX`（自畫框）：只記錄，不套用（A3 例外：串得上偵測才套用）。
- `next_camera_hint`：不改變追蹤器，只當作 H4 的鏡頭排名來評分。

規則閘門只當資訊（D340），Agent 選了閘門擋下的人時記 `RULE_OVERRIDE`。所以這個整合的上限由規則決定：Agent 只能在規則本地軌跡上挑人，預測只是建議，接回仍靠規則門檻（D356 的描述）。

### 3.2 實驗設定

**劇本**：16 段 LIVE 錄製，四類困難：A 相似衣著多人交錯、B 3–10 秒長盲區後重新出現、C 多出口分支、D 遮擋與真正離開。原本 9 段（#652，419.6 s，38 個主要決策點）加上 #665 補的 7 段（625.0 s，30 個重現點），合計 1044.6 s、68 個主要決策點（A 3 段／B 5 段／C 6 段／D 2 段）。#665 的劇本與 GT 是在沒看過任何組輸出時凍結的（D349）。簡單基準 r004 A4-1、B4-1 依預先登記分開報告，不參與判定。

**決策點與評估窗**：複雜決策點由劇本與 GT 事先決定，不由任何組的輸出決定；每點的評估窗是 `[t_dp, t_dp + 3 s]`。所有組重播同一份案例檔，目標由案例的 `start`／`pick` 指定。

**指標**（預先登記 §4，所有組共用 `e3_scoring.py`）：

- 框判定主準則：框中心在 GT 身體框內，或 IoU ≥ 0.3；IoU 準則（IoU ≥ 0.3）必報，作為穩健性。
- 分母一律是 GT 可見時間。每 tick 分成 CORRECT、錯人、定位不準、失聯、錯鏡頭；目標哪裡都不可見時另記盲區誤鎖。
- **錯人秒**＝錯人＋錯鏡頭（H1 主指標）；跟對率＝CORRECT／GT 可見 tick。
- **決策點正確**：評估窗內至少一個 CORRECT tick，而且沒有錯人或錯鏡頭 tick；Agent 組用 K=3 多數決。
- 鏡頭 top-1／top-3：失聯後重新出現時，「下一台看哪裡」的排名是否包含目標第一個可見的鏡頭；沒給排名算未命中，不排除。
- API 失敗、逾時或格式退回算缺漏資料，由 B1 規則繼續，該點照常計分。

**統計**：以段為單位的 cluster bootstrap，2000 次，種子 660，95% 百分位區間；決策點用 McNemar 檢定。每個假設只有一個主要檢定，結論用「成立／不成立／無法判斷／探索性」四種字眼之一。

**先登記、後看結果**：預先登記（[`E3_PREREGISTRATION_20261122.md`](../evaluation/E3_PREREGISTRATION_20261122.md)）在任何付費呼叫之前提交，判定一律用 PR #662 合併版的 `e3_scoring.py`（SHA-256 `acacce396f27e0d7c8bf03d527b22272f2622376ed4a43ae6db0842353f87d08`）。合併後的四次修訂都在**還沒計算或看過任何 E3 分數**時寫入，而且都不改 §4 評分與 §6 門檻：

#### 3.3.4 失敗機制（事後診斷，不改判定）

F4 報告 §8.1 引用的 Opus 診斷，回答的問題是「不成立是不是程式錯誤」，結論是：**是這個整合下的 Agent 較差，不是程式錯誤。**

### 3.4 討論

**為什麼在這種整合方式下沒有勝過規則。** 失敗集中在兩件事，都和「答案怎麼接進規則追蹤器」有關，不在單張影格的辨識：

1. **判斷目標不在**：Agent 很少答「不在」（62/1684），目標不在畫面時仍會選一個人；34% 被採用的 `SELECT` 落在看不到目標的鏡頭。這也讓失聯秒降低、盲區誤鎖秒上升（3.3.2）。
2. **每次採用都重設追蹤器**：A1／A2 約 84% 的呼叫被採用（A2 1423/1684），AMBIGUOUS 時 Agent 選錯人或顯示框推導選到旁邊的人，都會把規則原本正確的追蹤換掉。C 類錯人秒（67.6 → 151.3 s）與錯誤切鏡（19 → 79.7 次）大增都來自這些重設。A3 因為同時只有一個在途呼叫、過期答案會丟棄，結果接近 B1（+4.3 s），這不是 Agent 有效的證據。

**辨識層 F1 高，整合後沒有提升。** W1 在 r004 兩事件的 422 格分層樣本上，看圖 Agent 的逐格辨識明顯較好：主準則（K=3 多數決，W1 主結果）整體 F1 0.957 對規則 0.523，差 +0.433 [0.324, 0.566]；用統一評分器的 IoU 準則重算是 0.887 對 0.518。W1 也已經看到「不在」的代價：目標在畫面外的格子，看圖 Agent 的「不在」答對率 0.89，規則 0.95。E3 顯示，在目標出現時辨識較好，不足以讓切換決策變好：決策時的瓶頸是「判斷目標不在」與「答案如何生效」，而依附整合把這兩件事交給了規則追蹤器的重設介面。兩個實驗的資料也不同（W1 是 r004 兩個簡單事件、離線逐格；E3 是 16 段困難 LIVE 劇本），不能直接相減。

### 4.1 設計（A-open）

預先登記：[`E5_PREREGISTRATION_20261123.md`](../evaluation/E5_PREREGISTRATION_20261123.md)；介面契約：[`E5_AOPEN_INTERFACE_V1.md`](../contracts/E5_AOPEN_INTERFACE_V1.md)。

**組別。** B1（規則，沿用 E3 執行檔，固定在 E3 版本，不重跑）；B2（B1＋空間排序，沿用，只附報 top-k）；**AO**（A-open，離線同步，K=3，主結果）；**AO-L**（模擬即時，K=1，分開判定）。E3 的 A2 列為附報對照，沒有重跑也沒有判定。

**A-open 的定義**（預先登記 §2.2）：

1. **Agent 直接建立或接管軌跡**：回答 SELECT（選偵測框）或 OWN_BOX（自畫框）時，這個框就是目標，從下一個 tick 起顯示，不經規則的顏色、分數或圖門檻。
2. **下一台預測驅動搜尋**：每次回答附 `next_camera_ranking`（最多 3 台）；目標失聯時，下一次提問提前（最小間隔 1.0 s）。
3. **判斷之間由中性追蹤器延續**：不看顏色，只在同一台鏡頭內用 IoU ≥ 0.3 把目標框接到下一個 tick 的偵測框；接不上最多滑行 2 個 tick（0.4 s），之後顯示失聯。中性追蹤器不換鏡頭、不自己找新目標。
4. **規則只附資訊、不否決**：請求附規則追蹤當時的狀態與每個框的閘門結果，規則的決定不改變 AO 的顯示。
5. NOT_VISIBLE：不顯示並記下排序；UNCERTAIN：不改狀態；STILL_HERE_OCCLUDED：在原鏡頭以最後位置顯示，保留 10 個 tick（2.0 s）。

**資源限制（唯一的限制）**：每 2.0 s 定期提問（追蹤中也問）；每段呼叫上限 ⌈片段秒數 ÷ 2.0 × 1.5⌉；逾時 30 s（離線同步）；AO 合計費用上限 USD 25；模型 `gpt-6.1-terra`；格式不合格不重試。

**AO-L 的執行方式**：答案在「提問時間＋實測延遲」之後的第一個 tick 生效；答案到達時，Agent 選的框若不能從提問時刻用 IoU ≥ 0.3 逐 tick 串到現在，記 EXPIRED、不套用。判定規則同 H8a，分開判定，結論一律加註「K=1」。

**唯一剩下的規則依附（照實揭露）。** 目標種子（參考截圖與第一次提問的時刻）取自規則第一次 ACQUIRE；在這之前 AO 不顯示任何東西。B1 也從同一次 ACQUIRE 開始，所以兩組起點相同。代價是：E5 測不到「Agent 自己找到第一個目標」的能力。
