## 0. 和 E3、E4 的關係

- **E3**（#678）：Agent 依附規則：只能選規則本地軌跡上的人、預測只是建議、接回靠規則門檻。結論只能寫「**這種依附整合下 H1／H2／H4 不成立**」。E5 用它當對照，不重新判定。
- **E4**（#681）：條件式覆寫＋採用前驗證，仍是依附設計，依 D356 中途停止（10/48 個執行、沒有評分）。資料保留，只當探索性附錄，不進 E5 的判定。
- **E5** 單純比較 Agent 與規則：Agent 完全開放處理，唯一的限制是資源（§2.3）。

E5 的劇本和 E3 相同，而且是在看過 E3 結果之後設計的。這一點照實揭露：門檻沿用 E3 已寫死的判定函式和數值（§5），不為 E5 另訂比較寬鬆的門檻。

## 1. 要回答的問題

在同一批 RT-DETR 偵測與畫面上，讓 Agent 直接決定追蹤目標（選框或自畫框、預測下一台鏡頭），判斷之間由不看顏色的中性追蹤器延續；在只受資源限制的條件下，它比規則（B1）少錯人秒嗎？跟對率呢？盲區誤鎖和重新出現點呢？

### 2.1 共同輸入

- 16 段：E3 原本的 9 段，加上 #665 的 7 段。tick 間隔 200 ms，畫面 320×180。總長 1044.6 s（5223 tick）。
- 偵測：E3 凍結的 RT-DETR 偵測索引，人物類別，分數 ≥ 0.15（`CAM_ENTRY` ≥ 0.05），和 B1 的輸入相同。Agent 另可自畫框補偵測器漏掉的人。
- 畫面：凍結 PNG。場景資訊：E3 A2 用的 scene context（`scene_context_sha256` 相同，D348，不做牆面裁切）。
- 目標種子：E3 的參考截圖規則（規則第一次 ACQUIRE 時截取，不讀 GT）。

### 2.2 A-open 的定義（介面細節見契約）

1. **Agent 直接建立或接管軌跡**：回答 SELECT（`camera_id`＋`detection_id`）或 OWN_BOX（`camera_id`＋`box_xyxy`）時，這個框就是目標，從下一個 tick 起顯示，不經過規則的顏色、分數或圖門檻。
2. **Agent 的下一台預測驅動搜尋**：每次回答都附 `next_camera_ranking`（最多 3 台），這就是搜尋順序，H8c 用它評分。目標失聯時，下一次提問提前到最小間隔，請求把排序中的鏡頭放在前面。
3. **判斷之間由中性追蹤器延續**：不看顏色，只在同一台鏡頭裡用 IoU ≥ 0.3 把目標框接到下一個 tick 的偵測框；接不上時最多滑行 2 個 tick（0.4 s），之後顯示失聯，等下一次 Agent 判斷。中性追蹤器不換鏡頭、不自己找新目標；換鏡頭只能由 Agent 決定。
4. **規則只附資訊、不否決**：請求附上規則追蹤當時的狀態（狀態、作用中鏡頭、失聯 tick 數）和每個框的規則閘門結果，只當資訊。規則的決定不會改變 AO 的顯示。
5. NOT_VISIBLE：不顯示，記下排序。UNCERTAIN：不改目前狀態，中性追蹤器繼續。STILL_HERE_OCCLUDED：在原鏡頭以最後位置顯示（只有位置、沒有框），最多 2 s。

### 2.3 資源限制（唯一的限制；主設定寫死）

| 參數 | 主設定 | 說明 |
|---|---|---|
| `poll_s` | 2.0 s | 定期提問間隔，追蹤中也問 |
| `min_interval_s` | 1.0 s | 失聯時提前提問的最小間隔 |
| `call_cap_per_segment` | ⌈片段秒數 ÷ `poll_s` × 1.5⌉ | 每段每次執行的呼叫上限，到了就只靠中性追蹤器 |
| `timeout_s` | 30 s（離線同步）；AO-L 用實測延遲 | 逾時算 `PROVIDER_TIMEOUT` |
| `cost_cap_usd` | AO 合計 25；AO-L 見 §6 | ApiGuard 帳本上限，每個行程用自己的帳本（D352） |
| 格式驗證 | `agent_service` 的 JSON 驗證＋E5 的回答種類 | 不合格就當沒有回答，不重試，中性追蹤器繼續 |
| 模型 | `gpt-6.1-terra`（D237） | 所有付費呼叫都經 ApiGuard |

多種限制強度的比較（1 s／2 s／只在失聯時）列為後續工作，不在 E5 判定內。

## 3. 執行

- 離線同步（AO）：答案在提問後的下一個 tick 生效，和 E3 A1／A2 相同。
- 模擬即時（AO-L）：答案在「提問時間＋這次實測延遲」之後的第一個 tick 生效。這段期間中性追蹤器照常延續；答案到達時，Agent 選的框要能從提問時刻用 IoU ≥ 0.3 逐 tick 串到現在，否則記 EXPIRED、不套用（E3 §7 的規則）。
- K：AO 3 次；AO-L 1 次。試跑 1 段（E3-A1，K=1），結果排除，只檢查格式退回率和紀錄欄位，不看分數。

## 5. 假設與門檻（AO vs B1，16 段、68 個決策點）

差值都是「AO 減 B1」，用 16 段的合計秒數；95% 區間是段群集 bootstrap（`cluster_bootstrap`）。

### H8a（主要）錯人秒與跟對率

用釘選評分器的 `verdict_h1`，函式和數值都不改（E3 §6.1）：
- **成立**：錯人秒差區間整個 < 0，**而且** 跟對率差的區間下界 > −0.05，**而且** McNemar p < 0.05、偏向 Agent。
- **不成立**：錯人秒差區間整個 > 0，**或** 跟對率差的區間上界 < −0.05，**或** McNemar p < 0.05、偏向規則。
- 其他：**無法判斷**。少於 40 點或 8 段：探索性。
- 穩健性：IoU 準則（保守）下跟對率差的點估計比 −0.05 差時，結論加註「依賴框判定準則」。

### H8b 盲區誤鎖秒

- **成立**：AO − B1 的盲區誤鎖秒差區間整個 < 0。
- **不成立**：區間整個 > 0。
- 其他：無法判斷。

### H8c 重新出現點

- 單位：37 個重新出現點（REAPPEAR、BRANCH_RETURN、SCREEN_RETURN）。AO 有 K=3，所以分母是 111；B1 的分母是 37。排序取前一個 tick 的排序；沒給排序算未命中（同 E3 §6.3）。
- 主指標：top-1 命中率差（AO − B1）。區間用段群集 bootstrap，每段用自己的命中率合計。
- **成立**：區間下界 > 0。**不成立**：區間上界 < 0，或 AO 的 top-1 點估計 ≤ 隨機期望。其他：無法判斷。
- 另報：top-3、有排名的點數、重新出現後的重新取得延遲。

### H8d（時間允許）模擬即時

AO-L vs B1，規則同 H8a，**分開判定**，不和 AO 合併。AO-L 只有 K=1，所以結論一律加註「K=1」。沒跑就寫「未執行」。

### 共同規則

- 四種字眼照 E3：成立、不成立、無法判斷、探索性。H8a 是主要結論；H8b、H8c 各自報告，不做多重比較校正，也不合併成一個總結論。
- 判定只依登記時的評分器和包裝程式版本。收資料後有任何修改，照 E3 §9，兩版都報。
- 不論結果如何，都不能推翻 E3 的結論。E3 和 E5 回答的是兩個不同的整合方式。

## 7. 停止條件

照 E3 §9，另加：
- 試跑的格式退回率 > 20%：先修提示或解析，不付費重跑。
