## 2. 評分定義（摘要，正式條文見預先登記 §4–§5）

- **框判定只有一個函式** `judge_box`：規則框、Agent 選的索引框、Agent 自畫框、索引外偵測一律相同。GT 身體框先裁到畫面內。**主準則**＝框中心在身體框內 **或** IoU ≥ 0.3（W1 的定義）；**IoU 準則**＝IoU ≥ 0.3。IoU 命中一定是主準則命中。
- **四類錯誤**（分母＝GT 可見 tick）：錯人（顯示的鏡頭看得到目標，但框不在目標上）、定位不準（框中心在目標上但 IoU < 0.3，只在 IoU 準則出現）、失聯（目標可見卻沒有顯示）、錯鏡頭（顯示的鏡頭看不到目標、別台看得到）。分母外：盲區誤鎖、盲區正確、盲區續顯。「錯人秒」＝錯人＋錯鏡頭。
- **r004 的 GT 可見**＝（a）索引中有任何類別、分數 ≥ 0.3 的偵測框中心落在投影身體框內（D325 準則）**或**（b）W1 像素證據：身體框 ≥ 50% 在畫面內且框內紅色像素 ≥ 15。下表另列「只用偵測可見」（只有 a，等於 D325 的分母）作為敏感度。

## 4. 差異的原因（逐項）

1. **規則基準 0.970→0.944、0.906→0.897（只用偵測可見）**：舊評分器的「續顯」規則（框閃一下時 ±0.6 s 內偵測到就算對）在**目標哪裡都偵測不到**的 tick 也記 CORRECT，分子多算，分母沒有：A4-1 6 個 tick（226／233 → 220／233），B4-1 2 個（184／203 → 182／203）。新評分器把它們記成「盲區續顯」，不算對也不算錯。舊的「含自畫框跟對率」1.009、1.006 大於 1 也是同一原因，新評分器結構上不會超過 1。
2. **規則基準 0.944→0.904、0.897→0.889（主結果）**：分母改成 GT 可見後變大（A4-1 46.6 → 50.0 s，B4-1 40.6 → 41.4 s），多出來的是偵測器沒有框、但畫面中看得見目標的 tick，規則在這些 tick 是失聯（A4-1 失聯 2.6 → 4.8 s，B4-1 4.2 → 4.6 s）。上面 6／2 個續顯 tick 在像素證據下其實可見，改記 CORRECT。
3. **Agent 組離線跟對率 0.916→0.981（W2 A，B4-1）、0.970→0.960（A4-1）**：舊的 `follow_rate` 不算自畫框（含 Agent SELECT 了索引外偵測的情形，W2 評分器把它當自畫框），那些 tick 留在失聯；新評分器把每個顯示的框都用同一個判定計分。舊的「含自畫框」數字雖然計入，但 `vision_agent.overlay` 對自畫框只用未裁切身體框的 IoU ≥ 0.3，框中心在目標上的自畫框多被記成「自畫框錯」（W2 A B4-1 1.6 s）。
4. **舊的盲區誤鎖（只用偵測可見 0.7–1.4 s）在主結果全部變 0**：那些是 Agent 自畫框畫在偵測器漏掉、但畫面中可見的目標上。只用偵測可見會把這種情況記成「盲區誤鎖」，正好與 H5 要量的方向相反；這是把 r004 的 GT 可見改成「偵測 ∪ 像素證據」的理由。
5. **#648 的 IoU 準則數字（B4-1 跟對率 0.761、錯人 6.3 s）不是同一把尺**：當時只有 Agent 的索引外框用 IoU，規則框與索引框仍用中心點。新評分器對所有框一律用 IoU 準則後：
   - 規則自己在 B4-1 就有 10.0 s 定位不準：規則顯示的框有 48 個 tick 是 `sports ball`（41）、`vase`（7）等非人物類別的小框（RT-DETR 在渲染畫面把目標判成各種 COCO 類別；A4-1 也有 `fire hydrant`、`parking meter` 等，但多數 IoU ≥ 0.3）。規則 IoU 準則跟對率 B4-1 0.647、A4-1 0.872。
   - W2 A 離線 IoU 準則跟對率 0.824（規則 0.647），錯人 0.2 s、定位不準 6.5 s。#648 的「錯人 6.3 s」在新分類下大部分是定位不準（框在目標上但太小），不是錯人。
   - 逐 tick 轉移（W2 A 離線，B4-1，k0／k1）：規則 IoU 正確的 tick **沒有一個**被 Agent 改成不正確；規則已經定位不準、Agent 也定位不準 27／34 tick（多數是 Agent 選了規則正在顯示的同一個小框），規則定位不準→Agent 正確 23／16 tick，規則失聯→Agent 正確 17／17 tick。所以 W2 文件與 #648 的「Agent 用很小的非人物框取代規則已正確的人物框」在統一評分下不成立；成立的說法是「規則與 Agent 都常顯示偵測器給的非人物小框；IoU 準則下兩者都受罰，Agent 較少」。
6. **即時模式**：所有看圖組的即時結果與規則逐 tick 相同（新評分器下仍是增益 0），與已發表結論一致。
7. **W1**：主準則定義與 W1 相同，整體 F1 逐位重現（裁切身體框在三位小數內沒有影響）。IoU 準則下 terra 看圖自畫框 F1 0.957 → 0.887、規則 0.523 → 0.518，差距仍約 +0.37。分層 bootstrap 區間沒有用 IoU 準則重算（見「未驗證」）。
8. **H4**：只用偵測可見時與已發表逐位相同（B4-1 A2 top1 8／40、top3 37／40；C2 8／40、9／40）。主結果多了目標只有像素證據可見的 tick（A4-1 18 → 28、B4-1 40 → 44）：B4-1 A2 top1 8／44 仍低於隨機 14.0，top3 39／44 對隨機 34.2；結論不變（描述性訊號，不支持 H4）。
9. **D325（覆核架構）**：LLM 組的顯示與規則逐 tick 相同，所以數字等於規則；舊、新差異的原因同 1、2。
10. **API**：W2 成本由回應的 `usage` 依 `price_usd` 重算（A2／C2 含第一階段），主實驗 10 組合計 USD 8.145；ApiGuard 帳本 `caller=w2_agent` 為 USD 8.904，差額是快取比較的 95 次呼叫與帳本以估計值記的列，沒有逐列對帳。D325 成本取自各 run 的 `cost_usd`。延遲 p50／p95 是每個決策點的 API 實測延遲（A2／C2 為兩階段相加）。
