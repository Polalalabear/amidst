# 即時模式：4 m 加覆核後 A4 變差的原因（2026-11-16）

Model / effort：Sonnet 5.5 / high。全部用重播，沒有付費呼叫，沒有讀 API key，沒有 render。

## 結論

**這個退步是重播的「替身答題者」造成的，不是追蹤或裁決接法的錯。** `replay_advisor.py` 的 `OracleAdvisor` 用「離真實位置 1.5 m 內最近的候選人」當正確答案。A4 的場景有另一個人（NPC）跟目標並行，兩人只差約 1.3–1.4 m。當真正的目標不在候選名單裡時，替身把這個旁人當成目標，回答「2」；追蹤器照做，把追蹤搬到旁人身上，之後一直跟錯。真正的目標沒被列入候選，所以正確答案其實是 0。

把替身的容許距離改成 1.0 m（`--oracle-m 1.0`）後，4 m 加覆核在 38 段紀錄裡**沒有任何一段比 4 m 關閉差**（修正前有 5 段，每段掉 0.35–0.39）。

這也表示：先前「覆核不一定能讓追蹤變好」的 A4 結論，有一部分來自替身答錯，不能直接拿來否定影像裁決。但它同時留下一個真實的產品風險（見「還沒解決」）。

## 逐輪證據

紀錄 `sol2/a4_off_r2`（4 m、覆核；工具 `trace_ticks.py`，印每輪人物追蹤編號和位置）：

| 輪 | 真實位置 | 追蹤器估計 | 人物追蹤 |
| --- | --- | --- | --- |
| 27 | (5.4, 1.1) | (1.8, 1.1) | p2 (4.3, 1.9)、p3 (1.8, 1.1)、**p5 (5.3, 1.1)** |
| 提問 | | | 候選 = [p3, p2]；p5 離上一輪估計 4.5 m > 4 m，沒進候選 |

- 規則追蹤器約從第 22 輪起跟著 p3（另一個紅衣人，在目標後方約 3.5 m 同向走），所以「關閉」在這一段本來就跟錯。
- 第 27 輪 `SILENT_PICK` 問 [p3, p2]。替身算離真實位置距離：p3 3.68 m、p2 **1.36 m** → 因為 ≤ 1.5 回答「2」。真正的目標 p5 離真實位置 0.1 m，但不在候選裡。
- 第 34 輪答案到達（3.5 s 後），p2 沒有被「爭奪」（沒靠近別人），被套用，追蹤搬到 p2 (0.1, 1.3)。真實位置此時在 (9.4, 1.1)，之後 50 多輪都跟錯、最後失聯。
- 「關閉」的追蹤器因為 p3 恰好在第 36 輪之後被看成目標附近，反而跟對一段（第 36–54 輪），所以看起來「關閉比較好」。

全部 48 次提問（`asks_target_distance.txt`：每次提問的最近／第二近候選離真實位置的距離）：31 次最近候選 ≤ 0.6 m（確定是目標）、7 次離目標太遠（替身回 0）、**10 次最近候選在 0.64–1.42 m**：其中 9 次是上面這種旁人（1.28–1.42 m，第二近 3.64–3.68 m），1 次是 0.64 m（離目標很近，沒有問題）。1.0 m 正好落在這個縫隙裡。

## 還沒解決（不要過度解讀）

1. **替身 1.0 m 的選擇有來自這份資料的成分**：縫隙落在 0.64–1.28 m 之間，兩個 1.0 與 0.8 數字相同，所以結果在這個範圍內不敏感；但只有兩條路線，沒有在別的場景驗證。
2. **A4 路線鏡頭 4 m 覆核只是「不比關閉差」（0.38＝0.38），沒有「變好」**；A4 偵測本身的缺口（目標在室外鏡頭看得到卻沒被偵測）沒有被處理。
3. **真實風險：目標不在候選裡時，真的模型會怎麼答？** 這裡的候選（p3、p2）都不是目標，正確答案是 0。替身現在答 0，但真的模型只看到兩個紅衣人，可能挑一個。先前的實跑 38/38 答對是否包含這類「目標不在場」題目，沒有查（`adv_questions.json` 含角色代號，只能評分用，這個 session 沒有打開）。這個風險要靠實跑或單題測試才量得到，要花錢，需要使用者給金額。
4. **候選名單依「上一輪估計 ± 4 m」**：規則追蹤器已經落後目標 3.5 m 時，真正的目標會被排除在候選之外。可能的方向（未實作、未驗證）：候選改用人物追蹤本身的速度預測、或把提問範圍擴到所有 `people`；這會改變提問內容，重播量不出效果。
