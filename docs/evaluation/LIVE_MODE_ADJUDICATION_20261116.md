# 影像裁決測試結果：OpenAI 三個模型和 Colab 本機視覺模型（2026-11-16）

分支 `claude/feat-live-mode`（PR [#544](https://github.com/Polalalabear/amidst/pull/544)）。設計在 PR [#547](https://github.com/Polalalabear/amidst/pull/547) 的 `docs/design/LIVE_MODE_LLM_DECISION_V1.md` §0D。Colab 包的說明：[`ADJUDICATION_COLAB_PACK_20261116.md`](../operations/ADJUDICATION_COLAB_PACK_20261116.md)。

- Model / effort：Fable 5.2；effort 沒有記錄（這個 session 看不到自己的 effort 設定）。
- 這是工程量測，不是辨識、身分或實體安全的正式驗收。模型選了某個編號只代表「外觀最符合的假設」，身分仍然是未確認。
- 使用者核准的 OpenAI 上限是 USD 4。實際花費 0.88 USD。

## 1. 結論

1. **看圖的 OpenAI 模型分得出兩個紅衣人。** 36 題裡 sol6.1 和 astra6 各對 33 題（0.92），terra6.1 對 29 題（0.81）。三個模型多數決對 32 題。
2. **只看文字特徵明顯比較差**：同樣三個模型是 0.58–0.69。差距主要在演算法失聯的那 23 題。
3. **演算法在這 36 題裡只答了 13 題，對 10 題**；另外 23 題它正在失聯，沒有答案。
4. **Colab 上的 Qwen 視覺模型比較快（1.4–1.7 秒），但選不準**：看圖只有 0.56–0.58，而且偏向回答「1」。全部回答 1 就有 0.44。
5. **OpenAI 看圖要等 2.4–2.9 秒（中位數），p90 約 4.9 秒。** 回答格式 100% 合法。
6. **llama3.2-vision 在這版 Ollama 上載入失敗**，沒有任何結果。這是工具相容性問題，不是模型答錯。

## 2. 題目

36 題，來自即時模式實際出現的裁決時刻（6 次執行，只用演算法，追蹤器沒有改）。產生方式和隔離規則見設計稿 §0D。

- 每題有 2–3 個候選人（2 個的 31 題，3 個的 5 題）。
- 13 題是「追蹤範圍內有兩個以上紅衣人，演算法直接選最近的」；23 題是「演算法正在失聯，畫面裡有候選人」。
- 正確答案的分布：1 號 16 題、2 號 15 題、3 號 4 題、都不是 1 題。
- 隨機猜的期望正確率是 0.32；全部回答 1 是 0.44。

兩種輸入：
- **看圖**：目標第一次被鎖定時的裁切圖，加上當下 960×540 的鏡頭畫面（候選人的框上標編號）。OpenAI 是兩張圖分開送；Colab 是合成一張圖（左邊參考圖、右邊鏡頭畫面）。
- **文字特徵**：不給圖，只給從畫面量出來的數字：上下半身的平均顏色、框高、偵測分數、離上次推估位置幾公尺、需要的移動速度。

## 4. 怎麼讀這些數字

1. **使用者的方向有依據。** 裁決時丟圖給 OpenAI 的模型，正確率 0.81–0.92，遠高於只看文字特徵（0.58–0.69）和演算法（13 題對 10 題，其餘 23 題沒有答案）。最大的差別在失聯的時候：看圖在 23 題裡對 18–22 題，這些時刻演算法完全沒有作為。
2. **延遲是 2.4–2.9 秒，p90 約 5 秒。** 「LLM 主導」時畫面要停這麼久。這段時間加在現有 1.2–2.7 秒的切鏡延遲上，會不會超過設計稿訂的底線（失聯秒數的中位數不比演算法多超過 1 秒），要實際接上去才知道。演算法在失聯時本來就沒有答案，所以等 LLM 不一定比較慢。
3. **sol6.1 的性價比最好。** 正確率和 astra6 一樣，每次 0.0023 USD，是 astra6 的五分之一。terra6.1 最便宜也最快，但正確率低 0.11（4 題）。36 題的差距不大，不能當定論。D237 定的預設模型是 terra6.1，要不要改成 sol6.1 是使用者的決定。
4. **本機模型目前不能用來做這個裁決。** Qwen 兩個視覺模型在 L4 上比 OpenAI 快一倍，格式也都合法，但正確率只比「全部回答 1」高一點。可能的原因有三個，都沒有驗證：
   - 模型太小。
   - 合成成一張圖以後細節太小。
   - 候選人由左到右編號，模型偏向第一個。
5. **文字特徵這條路效果有限。** OpenAI 的模型拿到上下半身顏色和位置連續性，也只有 0.58–0.69。這表示目前量出來的特徵不夠分辨，或者 320×180 偵測框對到 960×540 之後量到的顏色不夠準。這和設計稿備援方案第 4 項（追蹤器加下半身顏色）有關：那一項的效果可能也有限，要先量。

## 6. 限制

- 36 題來自 6 次執行，同一次執行裡的題目彼此不獨立。36 題裡差 1 題就是 0.03。這是工程上的判斷依據，不是統計結論。
- 題目集中在 CAM_W1（24 題）和 CAM_W2（9 題）。
- 路線是劇本自動走的，場景和人物是合成的（N6 分件人偶）。換成真人影像結果可能不同。
- OpenAI 和 Colab 的看圖輸入不完全一樣：OpenAI 是兩張圖，Colab 是合成的一張。兩邊的正確率不能完全對等比較。
- 每個模型每題只問一次，沒有量同一題重複問的一致性。
- OpenAI 的延遲包含從這台 Mac 到 API 的網路來回，呼叫是一個接一個送的。
- 參考圖是目標第一次被鎖定時的裁切圖。6 次執行第一次鎖定的都是劇本裡的目標；實際使用時如果第一次就鎖錯人，參考圖也會是錯的。
- 沒有量「把答案接回追蹤器之後，失聯秒數和跟對比例變成多少」。這次只量單題的正確率和延遲。
- llama3.2-vision 沒有結果。
