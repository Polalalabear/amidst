## 5. 偏差聲明（報告必附）

1. **所有難題段都是照規則弱點設計的腳本**（D331：使用者不親自玩，H1–H5 全部由腳本操作者產生）。路線是 Claude 看過 RELOCK 的狀態機、候選名單規則和 graph v3 之後，刻意挑規則可能出錯的地方，並避開會讓段落作廢的情況（例如開場擦身）。它們能說明「在這些情況下 LLM 有沒有幫上忙」，**不能**代表一般使用時的錯誤率。
2. **沒有真人的不可預測性**：走法、時機、停留都事先寫死，走路速度固定 1.2／2.5 m/s，不猶豫、不回頭看、不臨時改道；同一段重跑，玩家位置差 ≤ 0.01 m。真人操作可能遇到的情況（例如臨時停在兩台鏡頭之間、走得忽快忽慢）不在這份難題集裡。
3. **基準組不分弱點**：照原劇本走，用來確認規則在簡單情況已經夠好、LLM 不會更差。
4. **報告一律分類列結果**：H1–H5 五類各自一列，再和基準組分開；不把各類加總成一個總分或總跟對率。逐類型表的「LLM 較好／相同／較差段數」也分類列。
5. 對照組 H5-3、以及事件記 `NOT_PRODUCED`、`H1n` 的段，照樣列在表中，不刪。

## 7. 操作卡（全部腳本產生，D331）

使用者不親自玩。每段的操作都由腳本操作者照 JSON 的 `route_plan` 執行；人只負責啟動和保存 log。
