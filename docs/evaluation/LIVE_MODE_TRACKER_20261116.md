# 即時模式演算法改進：重播測試和實跑驗證（2026-11-16）

分支 `claude/feat-live-mode`（PR [#544](https://github.com/Polalalabear/amidst/pull/544)）。前一份報告：[`LIVE_MODE_ADVISOR_20261116.md`](LIVE_MODE_ADVISOR_20261116.md)（影像裁決接上後的兩輪實跑）。

- Model / effort：Fable 5.2；effort 沒有記錄（這個 session 看不到自己的 effort 設定）。
- 這一輪沒有呼叫任何模型，沒有花錢。
- 這是工程量測，不是辨識、身分或實體安全的正式驗收。

## 1. 結論

1. **把關聯範圍從 3 m 放寬到 4 m，是目前最有效的單一改動。** 重播 68 段紀錄：跟對 0.51 → 0.63，失聯 0.29 → 0.17，跟錯不變。20 次全新的實跑：跟對 0.47 → 0.65，失聯 0.28 → 0.09。後台的預設值已經改成 4 m。
2. **改善集中在 B4 路線**（重播 0.62 → 0.89，實跑 0.75 → 0.98）。**A4 路線沒有改善**（重播 0.45 → 0.41），那條路線的問題是目標在室外鏡頭有十幾輪完全沒被偵測到。
3. **上一輪加的「兩人靠近過就不採用答案」門檻太嚴**（1.2 m），幾乎擋掉所有答案。改成 0.7 m 後，3 m 範圍下加上「一定答對」的回答，跟對是 0.63，和「只放寬到 4 m」一樣。
4. **4 m 範圍下再加上裁決，重播裡沒有再變好**（0.61 對 0.63），在 A4 反而變差（0.32 對 0.41）。就算回答一定正確也是這樣，原因還沒有查出來。這是下一步要先弄清楚的問題。
5. **「LLM 主導」仍然最差**（0.38）。
6. **試過一個「跟著人的編號走」的新追蹤器，比現有的差**（跟對 0.39，失聯 0.47），已經移除。
7. **「關聯範圍隨失聯時間放大」會讓跟錯大幅增加**（0.18 → 0.27–0.32），預設不開。

## 2. 重播測試是什麼

`scripts/live_mode/replay_advisor.py` 把實跑時錄下來的偵測結果重新餵給演算法和裁決模組，不呼叫模型。偵測結果和追蹤方式無關，所以同一段紀錄可以拿來比較不同的演算法設定。

- 裁決的回答用錄下來的目標真實位置代替：等 3.5 秒後回來，而且一定答對。**這只用於評估**，後台的程式不會 import 它。它回答的問題是「就算模型每次都對，這套接法能做到多好」，是上限，不是模型的實際表現。
- 可信度：重播「關閉」設定時，和實際紀錄逐輪比較，527 輪 0 個差異。
- `scripts/live_mode/replay_bench.py` 一次跑多種設定並列出結果。

用到的紀錄共 68 段，全部來自 v2.3 的 A4 和 B4 兩條劇本路線：T1 的 12 段、兩輪裁決實跑的 36 段、這一輪新跑的 20 段。

## 6. 還沒弄清楚的事

1. **4 m 範圍下，加上一定答對的裁決，A4 的跟對反而變差**（0.41 → 0.32；回答越快越差，2 秒是 0.19）。正確的答案不應該讓結果變差，所以接法裡還有問題。可能的方向，都沒有驗證：
   - 答案回來時那個編號已經換人（編號對調每 100 次觀測約 1.3 次）。
   - 把演算法移到被選的人身上之後，下一輪又被 4 m 範圍內更近的人拉走。
   - 回答「都不是」之後的處理。
2. **A4 路線的偵測。** 目標在室外鏡頭有十幾輪實際看得到卻沒被偵測到（例：一次重播裡第 5–20 輪）。這是偵測率的問題，演算法和裁決都救不了。
3. **4 m 在 A4 沒有幫助，還讓跟錯略增**（重播 0.29 → 0.33）。範圍放寬的代價是比較容易接到旁邊的人。
4. **只有兩條劇本路線。** 68 段紀錄彼此高度相關，參數有「剛好適合這兩條路線」的風險。換路線、換人數或由人操作時，4 m 是不是仍然比較好，沒有量過。
5. **提高推論頻率**（只推論作用中鏡頭和鄰居）還沒做，重播測試也量不到它的效果，因為它會改變擷取的內容。

## 8. 限制

- 重播裡的裁決回答一定正確，是上限。實際的模型在兩個候選人的題目上兩輪 38 題全對，但樣本少。
- 重播只能比較「偵測結果相同時」的演算法差異，量不到會改變擷取內容的改動（推論排程、解析度）。
- 全新的實跑每種設定只有 2–3 次，機器負載高而且沒有控制。
- 路線是劇本自動走的，場景和人物是合成的。
