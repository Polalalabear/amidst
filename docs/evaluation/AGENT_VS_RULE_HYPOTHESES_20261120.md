- Model / effort（本文件撰寫）：Claude Opus 5.5 / high。
- 狀態：**計畫**。本文件沒有新的量測、沒有付費、沒有渲染。所有「現有證據」都引用已提交的文件，沒有重算。

## 0. 為什麼要這份文件

使用者 2026-11-20 重申的研究要求，重點有四個：

1. Agent 模式要**真的**由 API 或模型做決策，而且要知道空間資訊（鏡頭關聯、可行走連通），主動去找可能的鏡頭。
2. 要驗證的是：**在複雜情況下，Agent 的切換決策比一般演算法好**，因為它能直接看圖判斷是遮擋還是偵測失敗。不要讓規則過早擋下 Agent。
3. Agent／規則在**所有模式**都能切換，包括查找。
4. 用 Agent 看圖辨識，是否比 RT-DETR 加規則的判斷好。

到目前為止，專案做了很多工程（開關、注入點、難題集工具、即時模式裁決），但**沒有一項結果能檢驗第 2 點**：預錄比較的場景太簡單、沒有送圖；8785 的 Agent 被閘門擋下沒有呼叫 API；LIVE 有送圖，但 Agent 只在規則允許的時刻、只對規則篩過的候選發言。本文件先把問題寫成可以被推翻的假設（§A），再對照現況證據（§B），最後才談資料、實驗與工作（§C–§F）。

## A. 研究問題與假設

**總問題**：在跨鏡頭追蹤的複雜情況下，一個能看圖、知道鏡頭空間關係、可以主動選擇要看哪裡的 Agent，是否比固定規則做出更好的切換決策與辨識？如果是，優勢從哪裡來，代價是多少？

每條假設都寫成可以被推翻的形式。「預期方向」是事前宣告的，結果出來後不改。

### H1 切換決策（主假設）

> 在複雜情況（c1–c6）下，看圖＋空間資訊的 Agent 組，切換決策優於規則組。

| 項目 | 內容 |
| --- | --- |
| 自變項 | 決策者：規則組 vs Agent 組（看圖＋空間資訊＋閘門當資訊，§A H3）。 |
| 依變項（主要） | **錯人秒**（系統顯示的框不在目標上的秒數，含失聯期間跟到別人）與 **跟對率**（目標可見秒中顯示正確的比例）。 |
| 依變項（次要） | 接回延遲（目標重新可見到系統顯示正確，秒）；錯接次數（連續 ≥ 2 tick 的錯人區段數）；正確宣告「不在任何畫面」的秒數；每決策點的成本（延遲、USD）。 |
| 比較組 | 同一段錄製劇本／同一份偵測輸入下的規則組；成對比較（§D.0）。 |
| 預期方向 | Agent 組的錯人秒**較少**，且跟對率**不低於**規則組；在 c1、c4 的決策點上 Agent 的單點正確率高於規則。 |
| 推翻條件 | 在預先登錄的複雜段集合上，下列任一成立即判 H1 **不成立**：(a) 錯人秒的成對差（Agent − 規則）的 95% 區間上界 ≥ 0（沒有減少）；(b) 跟對率下降超過 0.05 且區間不跨 0；(c) 決策點正確率的 McNemar 檢定沒有顯示 Agent 較好（不一致對中 Agent 勝的比例的 95% 區間包含 0.5）。只有 (a)(b)(c) 都朝預期方向才算支持。 |

**為什麼主要指標是錯人秒，不是跟對率**：(1) 錯人比失聯危害大——系統自信地指向錯的人，比誠實說「找不到」更誤導；(2) 跟對率的分母是「目標可見秒」，在目標長時間不可見的段（c3、c4）分母很小，跟對率會被少數 tick 主導；(3) 覆核架構下的 LIVE 實測已經顯示「答對了卻沒提高跟對率」（§B），錯人秒能看出 Agent 是否至少避免跟錯。跟對率當共同主要指標，是為了防止 Agent 靠「一直說不在」來降低錯人秒——兩者要一起看。

### H2 機制：優勢來自看圖辨別「遮擋／偵測失敗」與「真的不在」

> 如果 H1 成立，Agent 的優勢主要來自看圖：它能分辨「目標被遮擋或偵測器漏掉」與「目標真的離開這台鏡頭」，因此不會像規則那樣在偵測消失時立刻判失聯或轉移。

| 項目 | 內容 |
| --- | --- |
| 自變項 | 四組消融（2×2）：給圖 {有, 無} × 給空間資訊 {有, 無}。「無圖」組只拿文字特徵（框座標、顏色摘要、分數、軌跡摘要，和 D325 請求同類）；「無空間」組拿不到圖與鄰接資訊，只知道鏡頭代號。 |
| 依變項 | (1) 在 c2 決策點（GT 說目標在畫面內但被遮擋或偵測漏掉）上，判斷「仍在此鏡頭」的正確率；(2) 在「目標真的離開」的決策點上，判斷「已離開」的正確率；(3) H1 的錯人秒與跟對率。 |
| 比較組 | 四組互相比較，以「有圖＋有空間」為完整組。規則組當外部對照。 |
| 預期方向 | 「有圖」兩組在 c2 決策點的正確率明顯高於「無圖」兩組（主效應）；「無圖＋有空間」接近規則組。 |
| 推翻條件 | (a) 有圖 vs 無圖在 c2 決策點正確率的成對差 95% 區間包含 0 → 「看圖是優勢來源」不成立；(b) 若 H1 成立但優勢主要來自空間資訊（無圖＋有空間 ≈ 完整組），則 H2 不成立，改寫為「優勢來自空間推理」。 |

### H3 規則閘門應該是給 Agent 的資訊，不是硬擋

> 在 Agent 模式下，把規則閘門從「硬性擋下」改成「附在請求裡的資訊」，Agent 組的決策會更好，而且錯人秒不會因此增加。

要改成資訊的閘門（下表）；**不改**的硬擋：GT 隔離（Agent 不得取得 GT、渲染軌跡、可見性、深度）、付費護欄（`ApiGuard`）、身分輸出（永遠 `UNCONFIRMED`）、schema／回應驗證（格式不合法仍退回規則）。

| 閘門 | 位置 | 現在的效果 | 改成資訊時給 Agent 的內容 |
| --- | --- | --- | --- |
| `GRAPH_NOT_APPROVED` | `src/amidst/q1q5/candidates.py`（`scope_unapproved`） | 圖或 scope 未 G4 核定 → 所有轉移排除，候選 0（#629：A4-1 16 筆、B4-1 118 筆全擋） | 每條轉移附「核定狀態：DRAFT／未核定」 |
| `TOPOLOGICAL_ONLY`／`UNKNOWN` 授權 | `graphs.transition_authorities` | 22 條轉移中 20 條 `TOPOLOGICAL_ONLY`、2 條 `UNKNOWN`；可通行 0 條（#629） | 每條邊附授權等級，Agent 可以引用但要在理由裡標示 |
| `AMBIGUOUS_HANDOFF` | `src/amidst/q1q5/cross_camera_demo.py` L198／L210 | 合格候選 > 1 → ABSTAIN | 把所有合格候選和它們的圖給 Agent 選 |
| 顏色篩選 | `cross_camera_demo.py` `known_colors` 交集；LIVE `advisor.py` `d.get("color") == "red"` | 顏色不交集或不是紅色 → 不列入候選 | 顏色摘要當特徵附上，不篩掉 |
| 分數門檻 | LIVE 0.15（`detector.py`）；預錄評分 0.3 | 低分框不進候選 | 低分框（例如 0.05–門檻）另列「低信心框」並附裁切圖 |
| 發問條件 | LIVE `LiveDecider`：≥ 2 個紅衣候選、`gate_m = 3.0` m 內、失聯 ≥ 2 tick | 單一候選、候選在 3 m 外、或零候選時不問模型 | Agent 自己決定要不要看；規則的「不問」理由附上 |
| `MAX_REASON_CODES = 4` | Agent 回應驗證 | 超過 4 個理由碼 → `INVALID_RESPONSE` 退回規則（D325 §5：A4-1 約 12% 退回） | 這是格式閘門，保留，但截斷或改提示（不是決策閘門） |

| 項目 | 內容 |
| --- | --- |
| 自變項 | 閘門模式：硬擋 vs 只當資訊（其餘條件同 H1 的完整 Agent 組）。 |
| 依變項 | H1 的主要／次要指標；**被閘門擋下的決策點**上的正確率；Agent 選了「閘門會擋的候選」時的對錯（錯人風險）。 |
| 比較組 | 硬擋組 vs 資訊組，成對。規則組當外部對照。 |
| 預期方向 | 資訊組的跟對率較高、接回延遲較短；錯人秒不增加（非劣性界限 +0.5 s／段）。 |
| 推翻條件 | (a) 資訊組錯人秒比硬擋組多，且差的 95% 區間下界 > 0.5 s／段 → 閘門應保留為硬擋；(b) 資訊組與硬擋組在所有指標差異都在雜訊內，且被擋決策點 < 10 個 → 「無法判斷」，不能寫成支持。 |

### H4 主動搜尋：依空間資訊預測下一台鏡頭並主動去看

> Agent 根據鏡頭關聯與可行走連通，預測目標可能出現的下一台鏡頭並主動檢查，比規則更早找回目標。

| 項目 | 內容 |
| --- | --- |
| 自變項 | 搜尋策略：規則（等候選出現在出口區＋已核定轉移上）vs Agent 主動搜尋（每一步可要求「看鏡頭 X 在時間 t 附近的畫面」，有每步預算上限）vs 對照「不看圖的圖搜尋」（同樣的預測，但只看偵測框不看圖，分離「預測」和「看圖確認」）。 |
| 依變項（主要） | **接回延遲**：目標在某台鏡頭重新可見（GT）到系統正確指向它的秒數；未接回另計件數。 |
| 依變項（次要） | 前 1／前 3 預測命中率（Agent 預測的鏡頭排序中是否含 GT 下一台）；每次接回花的檢查步數與 USD；錯接次數。 |
| 比較組 | 規則組；「不看圖的圖搜尋」組。成對。 |
| 預期方向 | Agent 主動搜尋的中位接回延遲較短；前 3 命中率 ≥ 0.8。 |
| 推翻條件 | (a) 接回延遲成對差的 95% 區間包含 0；或 (b) 延遲變短但錯接次數增加（每段平均多 ≥ 0.5 次）；或 (c) Agent 主動搜尋與「不看圖的圖搜尋」相同 → 優勢只來自圖的鄰接，不是 Agent 判斷，H4 改寫為「圖搜尋優於規則」。 |

即時模式的單次呼叫要 4–5 s（D325 §7、LIVE 2.4–2.9 s 中位），主動搜尋每一步都要等。所以 H4 **分兩種模式報**：離線（可以等，延遲以模擬秒計，不含呼叫等待）和即時（呼叫等待算進接回延遲）。即時模式下 H4 可能不成立而離線成立；這時結論只能寫「離線成立」。

### H5 辨識：Agent 看圖判斷「這格有沒有目標、是哪個框」比 RT-DETR＋規則準

> 在單格判斷上，Agent 看圖（參考裁切圖＋當格畫面，可以標出新框）比 RT-DETR 偵測加規則的判斷更準，特別是在遮擋、距離遠、偵測分數低的情況。

| 項目 | 內容 |
| --- | --- |
| 自變項 | 判斷者：RT-DETR＋規則（偵測框＋顏色／分數門檻＋追蹤延續）vs Agent 看圖（兩種提示：(i) 只在 RT-DETR 框中選；(ii) 可以說「目標在畫面中但沒有框」並給大略位置）。 |
| 依變項 | 逐格的「目標在場」判斷：precision、recall、F1；「是哪個框」的選框正確率；「在場但沒框」的發現率（只有 (ii) 有）。 |
| 分層 | 遮擋比例（GT 投影框被其他物件遮住的比例：0、< 50%、≥ 50%）；距離（目標到鏡頭的公尺數分三段，或用 GT 投影框高度像素分三段）；RT-DETR 對目標的最高分數（無框、< 0.3、≥ 0.3）。分層變數**只在評分端計算**，不進請求。 |
| 比較組 | 同一批格子，成對。 |
| 預期方向 | Agent 的 recall 在「遮擋 ≥ 50%」「遠」「無框或 < 0.3」三層高於 RT-DETR＋規則；precision 不低於後者 0.05 以上。 |
| 推翻條件 | 三個困難層的 recall 成對差 95% 區間都包含 0；或 recall 上升但 precision 下降超過 0.05（只是更常說「有」）。 |

### H6 全模式可切換（前提條件，不是假設）

Agent／規則在每個模式都要能切換，而且切到 Agent 時**真的**由模型決策（呼叫紀錄可查）。這是檢驗 H1–H5 的前提，不是要驗證的假設。現況：

| 模式 | 能切換？ | 切到 Agent 時真的呼叫模型？ | 看圖？ | 空間資訊？ | 缺什麼 |
| --- | --- | --- | --- | --- | --- |
| Q1 查找（找鏡頭） | 只有 Q3 解析可走 LLM（`llm_parse_used`）；比對本身是索引查表（`q1_search.py`：「index-only」） | 比對不呼叫 | 否 | 部分（scope） | 沒有「Agent 看圖確認某鏡頭是否符合條件」的路徑 |
| Q2 查找（找人） | 8785 有開關（#604） | **否**：`GRAPH_NOT_APPROVED`，候選 0（#629／#635） | 否 | 被閘門擋 | #639（改接 `associate()`，等 Codex #623） |
| Q4 單格判斷 | 否 | — | — | — | 沒有 Agent 路徑；H5 需要新的離線評估器 |
| Q5 切鏡（預錄 8785） | 同 Q2 開關 | 否（同上） | 否 | 否 | #639 |
| 預錄離線（D325 harness） | 是 | 是（D325 共 USD 0.41） | **否**，只送代號與軌跡摘要 | 只有 `graph_edge` 旗標 | 送圖、送空間資訊、主動搜尋 |
| LIVE | 是（`/config advisor`） | 是 | 是（參考裁切＋960×540） | **否**（請求只有兩張 JPEG 與候選數） | 空間資訊、閘門改資訊、主動搜尋 |

**結論**：現在沒有任何一個模式同時滿足「真的呼叫＋看圖＋空間資訊＋閘門當資訊」。H1–H4 的完整 Agent 組目前**不存在**，必須先做（§E 的 W1、W2）。

## B. 現況對照：現有證據能證明什麼、不能證明什麼

證據強度用三級：**無**（沒有相關數據）、**弱**（有數據但條件不符，或樣本太小、只能當方向）、**部分**（條件符合假設的一部分，但缺關鍵比較組或接法）。

### C.3 最少要多少決策點才有意義

- **H1／H3（成對二元：每個決策點 Agent 對／錯 vs 規則對／錯）**：McNemar 檢定的檢定力取決於不一致對數。若規則在複雜決策點的正確率約 0.55（LIVE 覆核前 B4 跟對率量級）、Agent 預期約 0.80，不一致比例約 0.30，要在 α = 0.05、檢定力 0.8 下看出差異，約需 **40 個複雜決策點**；**建議 ≥ 60**，因為同一段內的決策點不獨立。分析單位用「段」做 cluster bootstrap，因此另要求 **≥ 8 段獨立段**（不同路線或不同劇本時段）。

- **H4**：接回事件 ≥ 20（每事件一個接回延遲），≥ 6 段。

## D. 實驗設計

### D.0 共通原則

1. **成對設計**：每條假設的所有組都吃**同一份輸入**——預錄：同一份偵測索引與畫面；LIVE：同一個 `?script=` 錄製劇本，評分以 `t_sim` 對齊，位置差 > 0.05 m 判 `NOT_COMPARED`（`LIVE_HARDSET_COMPARE_V1.md` §3）。決策點由規則組的 GT 事件定義，所有組共用。
2. **事前登錄**：每條假設的指標、分層、推翻條件、排除規則在實跑前提交（本文件就是 v1）；實跑後若要改，新增「事後分析」一節，不改原定義。
3. **GT 只在評分端**：Agent 請求只含畫面、參考裁切、偵測框（含低分）、鏡頭代號、圖的宣告與核定狀態、規則的建議與理由。不含 GT、渲染軌跡、`gt_visible`、深度、演員代號、劇本位置。每次請求寫 SHA-256 與欄位清單進紀錄，評分前用腳本檢查不含禁用欄位。
4. **K 次重複**：模型輸出有隨機性。每個 Agent 組 K = 3；規則組 K = 1（確定性；LIVE 規則組因追蹤器時序不確定，也跑 K = 3）。分析用 K 次的多數或平均，報 K 次範圍。
5. **延遲分兩種模式報**：
   - **離線（可等待）**：模擬時間在呼叫期間暫停；指標不含呼叫等待。回答「Agent 判斷本身好不好」。
   - **即時**：呼叫期間時間照走（LIVE 現況）；等待算進接回延遲與錯人秒。回答「現在的速度下能不能用」。
   兩種模式的結論分開寫；離線成立、即時不成立是可能且有意義的結果。
6. **模型**：主模型 sol6.1（`gpt-6.1-sol`，LIVE 看圖 0.92、每次約 USD 0.0023）；次模型 terra6.1（便宜、0.81）。astra6 只在 H5 抽樣比較（每次約 USD 0.011）。本機視覺模型（Qwen）在 LIVE 只有 0.56–0.58，不列主組。
7. **統計**：決策點層級用 McNemar；段層級用 cluster bootstrap（10,000 次）求成對差的 95% 區間；多個次要指標不做顯著性宣稱，只報區間。

## F. 停損與判讀

### F.1 什麼結果代表假設不成立

| 假設 | 判「不成立」 | 判「無法判斷」 |
| --- | --- | --- |
| H1 | §A H1 推翻條件 (a)(b)(c) 任一成立，且樣本達 §C.3 | 複雜決策點 < 40 或段 < 8 |
| H2 | 有圖 vs 無圖在 c2 決策點差異的 95% 區間包含 0 | c2 決策點 < 30 |
| H3 | 資訊組錯人秒超過非劣性界限 | 被擋決策點 < 10 |
| H4 | 接回延遲差區間包含 0，或錯接增加；即時與離線分開判 | 接回事件 < 20 |
| H5 | 三個困難層 recall 差區間都包含 0，或 precision 降 > 0.05 | 任一困難層在場格 < 50（該層判無法判斷，其他層照判） |

**停損**：(1) 若 H5 在困難層不成立（Agent 看圖不比 RT-DETR 好），H2 的機制基礎就不存在，H1 的實驗降為次要，先回報；(2) 若 H1 在離線模式都不成立，停止 W6（LIVE 即時接法），不再花錢在即時模式；(3) 任一實驗連續兩次因工程問題（格式退回 > 20%、重播不一致）無法比較，先修工具，不付費重跑。

### F.2 樣本小時怎麼寫結論

- 樣本未達 §C.3：只寫逐案表與「在 N 個決策點中 Agent 對 a 個、規則對 b 個，不一致 c 個」，**不寫**「支持」「優於」「證明」。
- 達到樣本但區間跨 0：寫「沒有觀察到差異（95% 區間 [x, y]）」，不寫「兩者相同」，也不寫「Agent 沒有用」。
- 只在離線成立：寫「Agent 判斷在可等待時較好；以目前 4–5 s 的單次延遲，即時模式未顯示優勢」。
- 只在某一類情況成立（例如 c4）：結論限定到那一類，不擴大到「複雜情況」。
- 覆核架構的結果（#597、#639、D325）一律標明「覆核架構」，不和主動架構的結論混寫。
- 所有結論附：場景範圍（合成渲染場景、graph v3、RT-DETR R18）、K、模型版本、每決策點成本；身分仍未確認；可行走連通是圖上宣告，不是實體可通行。
