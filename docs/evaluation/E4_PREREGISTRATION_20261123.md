## 0. 這是探索性實驗

E4 是**看過 E3 結果之後**、在**同一批 16 段劇本**上做的改良。設計直接針對 E3 §8.1 診斷出的失敗方式，所以不論結果如何，E4 都只能標成探索性：
它可以說明「這樣接 Agent 會不會比 E3 好」，不能當作 Agent 有效的獨立證據，也不能推翻 E3 的判定（D354）。要做確認性結論，需要新的劇本。

## 1. 要回答的問題

E3 的 A2 比規則差，主要原因有三個（#678 §8.1）：
- 每個被採用的 SELECT 都會無條件重設追蹤器。
- 34% 的採用落在提問時看不到目標的鏡頭上。
- Agent 很少回答「不在」（62/1684），而 hint 只跟著 NOT_VISIBLE 出現，所以 111 個重新出現點中有 102 點沒有排名。

E4 問的是：只在規則失聯或可信度下降時才讓 Agent 改追蹤、改之前先驗證，而且每次都要 Agent 給下一鏡頭排序，錯人秒、盲區誤鎖和排名覆蓋率會不會改善。

## 3. E4 決策器（`src/amidst/live_mode/service_decider_e4.py`）

和 E3 的 `ServiceLiveDecider` 共用提問生命週期（同步，答案在下一個 tick 生效）、人物追蹤器、參考截圖和 ApiGuard 傳輸。不同的地方如下，參數全部在這裡寫死：

### 3.1 (a) 可信追蹤

規則追蹤在某個 tick 算「可信」，要同時滿足：
1. 連續 `N_STABLE = 5` 個 tick（1.0 s）的狀態都是 `TRACKING`、`lost_ticks = 0`；
2. 這 5 個 tick 裡，估計位置每 tick 的移動都 ≤ `STEP_MAX_M = 1.0` m（5 m/s，超過算跳動）；
3. 作用中鏡頭上，離估計位置 1.5 m 內最近的偵測框（顯示框規則，和 E3 相同）存在、顏色等於目標顏色、分數 ≥ `SCORE_MIN = 0.4`（規則的連結門檻）。

可信時，Agent 的 SELECT／OWN_BOX **只記成候選**（`CANDIDATE_ONLY_TRUSTED`），不重設追蹤器；NOT_VISIBLE 也不解除鎖定。

### 3.2 (b) 條件式覆寫與採用前驗證

只有在規則**失聯**（`lost_ticks ≥ 2` 或 `SEARCHING`）或**可信度下降**（`TRACKING` 但不滿足 §3.1）時，SELECT 才可能被採用。採用前依序檢查，第一個不通過的寫進 `validation`：
1. `STALE`：答案的提問時間到現在超過 `MAX_AGE_S = 1.0` s。
2. `NOT_SEEN`：選的人在 `SEEN_S = 0.6` s 內沒有被看到（框不存在）。
3. `CONTESTED`：提問後另一個人在 0.7 m 內（E3 已有的檢查）。
4. `UNREACHABLE`：短期記憶（§3.3）還有效時，選的人離最後可信位置的距離 > `REACH_MARGIN_M = 1.5` ＋ `V_MAX = 2.0` m/s × 經過的秒數。這一條是「鏡頭真的看得到目標」的代理：不能用 GT，所以用物理上走不走得到。
5. `APPEARANCE`：選的人顏色和目標不同，而且 Agent 的 `confidence` 不是 `high`。

全部通過才採用（`APPLIED`），一次性重設追蹤器，和 E3 相同。OWN_BOX 照 E3 只記錄、不套用。

### 3.3 (c) 短期追蹤記憶

每個可信的 tick 更新「最後可信軌跡」：位置、鏡頭、時間。記憶的有效期是 `MEMORY_TTL_S = 8.0` s。過期後 §3.2 第 4 條不再檢查，改成要求 `confidence = high`，不會永久鎖定。記憶只用於驗證，不會自己顯示框。

### 3.4 (d) 回答種類與排序分開

提示在 E3 的 `SYSTEM_TEXT` 之後加一段 E4 說明（全文見 `service_decider_e4.E4_EXTRA`），改變三件事：
- 多一種回答 `UNCERTAIN`：看不出來。不改追蹤，規則繼續。
- 每次回答都要給 `next_camera_ranking`：最多 3 個鏡頭 ID，依「目標接下來最可能出現」排序，不論回答哪一種。H4／H7c 的排序取這一欄。只回 `next_camera_hint` 時，退回成單一候選。
- 明寫：沒有人清楚是目標時，回答 NOT_VISIBLE 或 UNCERTAIN；選到別人是代價最高的錯誤。

NOT_VISIBLE 只有在規則失聯或可信度下降時才解除鎖定。

### 3.5 提問時機

- LOST（規則失聯 ≥ 2 tick）：照 E3。
- DEGRADED：可信度下降時。取代 E3 的 AMBIGUOUS；規則可信時，即使 4 m 內有兩人也不問。
- RECHECK：每 4 s 一次，照 E3。可信時答案只當候選和排序。

最小間隔 1.0 s、參考截圖規則都和 E3 相同。

### 3.6 (e) 執行紀錄

每次呼叫多存這些欄位：
- 候選清單：每個框的 `detection_id`、鏡頭、框、分數、顏色、人物編號；
- Agent 選的 `detection_id`、`confidence`、`next_camera_ranking`；
- 請求原文：可變文字全文、前綴的 SHA-256、每張影像的 SHA-256。影像本身不存，可以由凍結輸入重建；
- 可信狀態和 `validation` 結果。

## 5. 假設與門檻（16 段，A2-E4 K=3）

差值都是「A2-E4 減比較組」的合計秒數，95% 區間用段群集 bootstrap（評分器的 `cluster_bootstrap`）。

### H7a 錯人秒

- **成立**：(i) A2-E4 − E3 A2 的錯人秒差區間整個 < 0，**而且** (ii) A2-E4 − B1 的錯人秒差區間上界 < +17.1 s（不劣界限，B1 合計 114.0 s 的 15%），跟對率差的區間下界 > −0.05。
- **不成立**：(i) 的區間整個 ≥ 0，或 (ii) 的區間整個 > +17.1 s。
- 其他：**無法判斷**。
- 只有 (i) 成立、(ii) 沒有成立時，照實寫「比 E3 好，但沒有證明不比規則差」。

### H7b 盲區誤鎖秒

- **成立**：A2-E4 − E3 A2 的盲區誤鎖秒差區間整個 < 0。
- **不成立**：區間整個 ≥ 0。
- 其他：無法判斷。對 B1 的差另報，不判定。

### H7c 有排名的重新出現點

- 單位：37 個重新出現點 × K=3 = 111，和 E3 相同。「有排名」指前一個 tick 的排序非空。
- **成立**：A2-E4 有排名的點 ≥ 56/111（一半以上；E3 A2 是 9/111）。
- **不成立**：< 20/111。
- 其他：無法判斷。
- top-1、top-3 命中率（分母 111，沒給排名算未命中）對隨機期望 0.125 和對 B1、B2 另報，不判定。
