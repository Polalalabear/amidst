## R-N 規格（和 AO 對齊；依 main `aopen/decider.py`、`neutral.py`、`tracker.py`）

| 項目 | 規定 |
| --- | --- |
| 起始 | 同一個種子 tick（B1 第一次 ACQUIRE）；從種子取初始估計位置，第一次決策為 FIRST |
| 提問時機 | POLL 2.0 s；**LOST_EARLY**：R-N 自己的中性追蹤器失聯且距上次 ≥ 1.0 s；同一個呼叫上限 ⌈秒數 ÷ 2 × 1.5⌉ |
| 候選 | 和 AO 相同的凍結偵測；規則只對其中 red、且投影得出地面點的框做距離閘門 |
| 狀態 | **讀 R-N 自己的中性追蹤狀態**（估計位置、失聯時間），不讀 B1 的追蹤狀態。失聯後中性追蹤器會清掉位置，所以 R-N 另存「最後已知位置與時間」並寫進紀錄；AO 的請求在失聯後沒有這項，是已知差異 |
| 生效 | 提問的下一個 tick，框用提問時的框；NeutralTracker 的參數不動（IoU 0.3、滑行 2 tick、遮擋 10 tick） |
| 沒有合格候選 | 主要版本＝UNCERTAIN（不改目標）；另跑 NOT_VISIBLE（清除）當敏感度。**兩個版本在執行前寫定** |
| 差異 | 規則不能畫框（OWN_BOX），AO 可以；AO 的請求帶著 B1 的追蹤狀態當資訊，R-N 沒有。報告列出，並報 OWN_BOX 佔比 |

規則追蹤器 `Tracker.update` 是 5 Hz 有狀態的演算法，沒有「只答一次」的函式，所以 R-N 需要新的轉接層（重用同一個距離閘門與顏色條件），**不能直接搬 B1 已選好的結果**；搬用只能標成「重播診斷」。R-N 改變了規則原本的頻率，結論只能寫「在中性追蹤器底座上」，不能寫成「規則（B1）較差／較好」。舊 16 段上的 R-N 只是事後描述。

## 統計與獨立性（預登要寫）

- 12 段是為了增加**獨立情境**，不保證統計能力。雙尾符號檢定（獨立、無平手）：8/8 的 p = 0.0078，10/12 的 p = 0.0386；不能直接套到 bootstrap 或決策點檢定。
- 開頭不同不等於獨立。#718 要列每段的路線、人物時序、相似人物來源、劇本家族，同家族的段合併成一個統計單位，並寫有效獨立單位數。
- 主要假設只列兩個並做多重比較校正：去錨定對 AO；開發資料上選定的組對 R-N。其餘為次要。要寫可偵測的效果大小；區間跨 0 就寫「無法判斷」。
- 開發資料 3 段太少，選組很不穩；選擇規則要預先寫死（含平手時取較簡單的組），不能解讀成勝負。
