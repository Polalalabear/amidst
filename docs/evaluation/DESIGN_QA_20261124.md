## 3. 現在要處理嗎

不改系統。改提問或採用規則就是新實驗，需重新預先登記；E5 已凍結。本期寫進論文討論與限制（#715），期限後再做：

| 問題 | 解釋 | 解法（未做） |
| --- | --- | --- |
| 目標不在時仍選人 | 每次都給候選，很少棄權 | 允許棄權，驗證「不在」正確率 |
| 採用後追蹤變亂 | 每次採用重設追蹤器 | 答案只當候選證據；連續一致或信心足夠才切換 |
| 介入時間不當 | 正常時多問就多一次改錯機會 | 不確定才問（H9 提案，未決定），加固定間隔對照 |
| 重疊鏡頭 | 未量測 | 定義主鏡頭與切換條件後單獨測 |
| 答案過期 | 延遲 | 較快模型、提前問、答案往後接續、延遲歸零對照 |
| 場景資訊看不到效果 | E3 111 點有 102 點無排名（F4 第 12、198 行）；E5 沒有無場景組 | 強制排名，成對比較有／無場景 |
| 外觀證據弱 | 顏色比例 | ReID 當候選證據，身分由人確認 |

建議順序：不花錢的上限分析 → 棄權與介入時機 → ReID 與查找實驗，判定用全新凍結劇本。

## 5. 放到算力充足的管理中心

查找與追蹤的**輔助架構**，不是身分辨識系統。以下是推論，沒有量測。

| 能力 | 算力的幫助 | 理由 |
| --- | --- | --- |
| 查找既有影像 | 應該最大 | 離線偵測建索引一次，可加鏡頭、取樣率、模型 |
| 即時追蹤 | 部分 | 可降延遲；但離線 AO 也沒贏規則，不只是算力 |
| ReID | 只是跑得動 | 目前沒有 ReID；可當候選證據接進重新鎖定 |

和 OpenAI API 的差別：延遲、呼叫次數、費用、資料不外傳、可微調。真實使用另需鏡頭校正、連通圖、時間同步；ReID 另需標註資料、誤認率評估與個資合規。

## 6. 系統瓶頸

1. 目標不在時仍會選人；2. 辨識好但追蹤沒變好（整合）；3. 即時延遲；4. 外觀證據弱；5. 預錄位置估計只有接近片尾的一個點（A4-1 49.8 s、B4-1 41.8 s；#714）；6. 合成場景、最多 8 台、無真實影像。排序是判斷，不是量測。
