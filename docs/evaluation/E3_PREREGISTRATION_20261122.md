## 3. 事件、決策點與目標種子

- **困難劇本（判定用）**：#652 的四類，錄成 `live-ab.case.v1`，狀態改成正式並釘 SHA 後才開跑：
  - **A** 相似衣著多人交錯；**B** 3–10 秒長盲區後重新出現；**C** 多出口分支（含目標出現在原本前 3 候選之外）；**D** 遮擋與真正離開。
  - 目標量：**至少 8 段、約 40 個複雜決策點**，四類都要有。
- **簡單基準組**：r004 A4-1（50 s）、B4-1（42 s），分開報告，不與困難劇本合併計算，也不參與門檻判定。
- **複雜決策點的定義在看結果之前固定**：以 #652 每段案例中 Codex 記錄的「預期決策點」（劇本 ID、時間、鏡頭、困難類型）為準，由劇本與 GT 決定，不由任何組的輸出決定。每個決策點附一個評估窗：`[t_dp, t_dp + 3 s]`（B 類為重新出現時刻起 3 s）。
- **同一套事件與目標種子**：所有組重播同一份案例檔（同 `case_id`、`seed`、`bindings` SHA），目標由案例裡的 `start`／`pick` 動作指定（同一 `est_xy`），各組不另選目標。

## 4. 評分器（`e3_scoring.py`，所有組共用）

### 4.1 框判定（`judge_box`）

規則框、Agent 選的索引框、Agent 自畫框、索引外偵測**一律用同一個函式**。GT 身體框先裁到畫面內。

- **主準則**：框中心在 GT 身體框內，**或** IoU ≥ 0.3。
- **IoU 準則**：IoU ≥ 0.3（必報；IoU 命中一定是主準則命中）。
- 一個 tick 顯示多個框時，任一框命中即算命中。沒有框的「只顯示鏡頭」tick 在鏡頭層級判定（該鏡頭目標可見，或 ±0.6 s 內可見）。
- LIVE 若沒有記錄顯示框，改用位置準則：系統估計位置距目標 ≤ 1.5 m 算對；此時 IoU 準則標「不可用」。**E3 要求 B 端每 tick 記錄顯示的鏡頭與框（像素）、A 端記錄目標在各可見鏡頭的 GT 框**（F3／F4 實作），否則 IoU 準則不可用，須在報告中列為偏差。

### 4.2 每 tick 類別與四類錯誤

分母**一律是 GT 可見時間**（目標至少在一台鏡頭可見的 tick）。

| 類別 | 條件 | 計入 |
|---|---|---|
| CORRECT | 顯示的鏡頭看得到目標，框命中 | 跟對 |
| **錯人** WRONG_PERSON | 顯示的鏡頭看得到目標，框不在目標上（LIVE 位置準則：估計距另一人 ≤ 1.5 m） | 錯誤 |
| **定位不準** MISLOCALIZED | 框中心在目標上但 IoU < 0.3（只在 IoU 準則出現）；LIVE 位置準則：估計距目標與他人都 > 1.5 m | 錯誤 |
| **失聯** LOST | 目標可見，卻沒有顯示（GAP／LOST／Agent 答「不在」） | 錯誤 |
| **錯鏡頭** WRONG_CAMERA | 顯示的鏡頭看不到目標，別台看得到 | 錯誤 |
| FALSE_LOCK／BLIND_OK／BLIND_HOLD | 目標哪裡都不可見時：有顯示／沒顯示／只顯示鏡頭的續顯 | 分母外，另報盲區誤鎖秒 |

### 4.3 指標（每段、每組；K 次先逐 tick 計算再平均）

- **錯人秒**＝錯人＋錯鏡頭（H1 主指標）；另報錯人、錯鏡頭分開的秒數。
- **跟對率**＝CORRECT／GT 可見 tick；四類錯誤各自的比例（與跟對率相加為 1）。
- **失聯秒**、**定位不準秒**（IoU 準則）、**盲區誤鎖秒**。
- **鏡頭 top-1／top-3 命中率**（附隨機期望 1 − C(n−v, k)／C(n, k)）：在失聯決策點，系統給出的「下一台看哪裡」排序前 k 名是否包含**目標在決策點之後第一個可見 tick 所在的鏡頭**。規則（B1／B2）的排序取規則實際搜尋的鏡頭順序；Agent 取 `next_camera_hint`／第一階段 `look_at`。
- **重新取得延遲**：每段「不是 CORRECT 的 GT 可見 tick」的連續區間（盲區 tick 跳過）從開始到下一個 CORRECT 的可見秒數；中位數、p90、設限（事件結束仍未接回）次數。
- **框 IoU**：顯示鏡頭看得到目標時，最佳框與 GT 框的 IoU 平均與中位數。
- **逐格 precision／recall／F1**：§6.4。
- **API**：每決策點延遲 p50／p95、USD（取自回應 `usage` 與 ApiGuard 帳本）、決策採用率（Agent 答案實際生效的比例；A3 另報過期丟棄率）、格式退回率。
- **決策點正確**：評估窗內至少有一個 CORRECT tick，且沒有錯人或錯鏡頭 tick；整窗失聯算不正確。Agent 組以 K=3 多數決決定每個決策點的對錯。

### 4.4 主準則

**判定一律用主準則**；IoU 準則必報，作為穩健性條件（§6）。理由：H1 問的是切換到對的人與鏡頭；統一重算顯示，IoU 準則會把偵測器在渲染畫面上給的非人物小框（規則與 Agent 都會顯示）一併記成定位不準（B4-1 規則 10.0 s），那是框的品質，不是切換決策。

## 5. 資訊邊界

### 5.1 可以進推論（Agent 請求、規則、B2 排序）

- 靜態場景幾何：牆面、門、出口區、由標定與牆面投影的地面覆蓋多邊形（不含遮擋以外的 GT）。

- 系統觀測：偵測框、分數、類別、顏色判定、系統由偵測＋標定算出的估計位置、渲染畫面像素、規則顯示與閘門結果（D340：閘門只當資訊）。
- 每項附來源 SHA-256；缺項標 `SCENE_CONTEXT_INCOMPLETE`。

### 5.2 只能用於評分（推論端不得讀取或 import）

- 可見性：LIVE `gt_visible`（renderer 射線檢查：3 個身體點中 ≥ 2 個在畫面內且到鏡頭的射線不穿牆；不檢查人與人遮擋）、r004 像素證據標籤。
- depth、GT 框、renderer 軌跡。
- **r004 的 GT 可見**＝索引中有偵測框中心落在投影身體框內（任何類別、分數 ≥ 0.3）**或** W1 像素證據（身體框 ≥ 50% 在畫面內且框內紅色像素 ≥ 15）。只用前者會讓「Agent 在偵測器漏掉、但看得見的目標上畫對框」被記成盲區誤鎖。

## 6. 成立與不成立門檻

統計：成對比較（同一段、同一決策點），以**段**為單位的 cluster bootstrap，2000 次，種子 660，95% 百分位區間。離線（A2）與模擬即時（A3）分開判定。三種結論：**成立**、**不成立**、**無法判斷**（寫「沒有觀察到差異，區間 [x, y]」）。

### 6.1 H1（A2 vs B1；A3 vs B1 另判）

- **成立**（三條同時）：錯人秒差（A − B1）的 95% 區間 < 0；跟對率差的區間下界 > −0.05；決策點正確的 McNemar 檢定（K=3 多數決 vs B1）p < 0.05 且 Agent 較好。
- **穩健性**（必報，不改變判定但寫入結論）：IoU 準則下跟對率差的點估計不得比 −0.05 更差；否則結論加註「依賴框判定準則」。
- **不成立**：錯人秒差區間 > 0，或跟對率差區間上界 < −0.05，或 McNemar p < 0.05 且規則較好。
- 其他情況：無法判斷。

### 6.2 H2（看圖的主效果）

- **成立**：A1 − B1 **與** A2 − B2 兩組的跟對率差區間都 > 0（或錯人秒差區間都 < 0）；**而且**在 D 類決策點，A2 判「已離開」的正確率不低於 B2 超過 0.05（差的區間下界 > −0.05）。
- **不成立**：兩組差的區間都包含 0 或為負。
- **改寫**：A1 ≈ B1（區間含 0）但 A2 > B2，表示增益主要來自空間推理與看圖的交互作用，H2 依此改寫，不寫「增益來自看圖」。

### 6.3 H4（空間資訊的主效果，排序）

- 樣本：困難劇本中目標失聯後重新出現的決策點（主要是 B、C 類）。
- **成立**：A2 − A1 的 **top-1** 命中率差區間 > 0，**而且** A2 的 top-1 命中率區間下界高於隨機期望，**而且** A2 重新取得延遲中位數低於 A1。B2 vs B1 同法另報。只有 top-3 改善、top-1 不高於隨機（W2 的情形）不算成立。
- **不成立**：top-1 差區間包含 0，或 A2 top-1 不高於隨機期望。

### 6.4 H5（逐格辨識）

- 協定沿用 [`W1_FRAME_EVAL_PREREG_20261120.md`](W1_FRAME_EVAL_PREREG_20261120.md)：同一批格子逐格獨立呼叫，規則＝Q4 判法（person、score ≥ 0.3、HSV），Agent＝看圖可選框／自畫框／答「不在」，K=3 多數決為主、逐格平均為敏感度；正樣本＝LIVE `gt_visible` 含該鏡頭。
- 格子取自困難劇本，分層：相似衣著同框、遮擋、遠小、沒有人物框、非人物類別框，間隔 ≥ 1 s；每層在場格 ≥ 50 才判定。
- **成立**：至少兩個困難層 recall 成對差區間 > 0，且 precision 下降 ≤ 0.05；**不成立**：這些層的區間都含 0，或 precision 下降 > 0.05。框判定用 §4.1 主準則，IoU 準則必報。

### 6.5 樣本不足

- H1／H2：困難劇本 < 40 個複雜決策點或 < 8 段；H4：< 30 個重新出現決策點；H5：某層 < 50 格。
- 不足時結果標成**探索性**，只寫逐案數字與區間，**不降低門檻**，也不寫「支持」「優於」「推翻」。
- 只在離線成立時寫：「可以等待時 Agent 判斷較好；以目前的延遲，即時模式沒有顯示優勢」。

## 7. A3 模擬即時規則

1. 每次呼叫帶時間戳：`t_call`（觸發的擷取時刻）、`latency_s`（該次呼叫的實測延遲，取自答案檔；重播時沿用同一次錄製呼叫的實測值，不重新抽樣）。
2. 答案在 `t_arrive = t_call + latency_s` 之後的第一個 tick 才生效；等待期間顯示照 B1 規則繼續。
3. 同時只允許一個呼叫在途；在途時不發新呼叫。
4. **接得上就接續**：答案指的是 `t_call` 時的框；從 `t_call` 到 `t_arrive`，在同一鏡頭以 IoU ≥ 0.3 逐 tick 串接系統偵測。串得上，就在 `t_arrive` 切到串接後的框並繼續追蹤。
5. **接不上就丟棄**：串接中斷（或答案是自畫框且 `t_arrive` 時沒有可串接的偵測），記 `EXPIRED`，不顯示過期結果，報告列出過期丟棄率。
6. 「不在，下一台看 X」答案在 `t_arrive` 生效時，只改變搜尋順序，不顯示框。
7. A3 判定只用模擬即時；F4 另跑一小段真的 LIVE 只作驗證，不參與門檻。

## 8. 預算

- OpenAI 累計到 **USD 90** 前不用另外詢問（D344）；到 90 就停並回報。
- 每筆付費呼叫都經 `ApiGuard`（dry-run 先估計、帳本記錄 `caller`），不允許旁路。
- 開跑前先跑一段（1 段 × A1／A2 × K=1）確認格式退回率與每點成本，再依估計排程。

## 9. 停止條件

- 試跑格式退回率 > 20%：先修提示或解析，不付費重跑。
- API 錯誤或逾時 > 10%（任一組、任一段）：停下檢查。
- 輸入重播發散（`CASE_DIVERGED`、`CASE_SOURCE_MISMATCH`）或 A1／A2 影像 SHA-256 不一致：停，修好後該段所有組重跑。
- 發現 GT 欄位進入推論（請求、提示、日誌出現 §5.2 欄位）：停，丟棄受影響的結果並回報。
- 累計花費到 USD 90。
- 評分器在收資料後有任何修改：所有組重算，兩個版本都報告。

## 10. 報告格式

- 每組、每段、每類（A–D）與合計；兩種準則；四類錯誤秒數與比例；決策點正確率；top-1／top-3 與隨機期望；重新取得延遲；API 延遲／成本／採用率。
- 原始紀錄路徑（LOCAL）與 SHA-256、評分器 commit SHA、劇本 `case_id` 與 SHA。
- 依 §6 用「成立／不成立／無法判斷／探索性」四種字眼之一寫結論。
