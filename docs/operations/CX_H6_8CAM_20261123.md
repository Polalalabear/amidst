## 行為與原因

`Demo.call(q_core_track)` 原本只對 D124 run 使用 `ServiceTrackDecider`，其他 run 拒絕 `manual_seed`，8CAM 只回傳 Agent 未接線，B-05 的 bootstrap 還覆寫成 `NotApplicableAgent`。現在只對已註冊的 B-05 和 A4-1-8CAM 使用 `service_core_track.core_track`：既有 core LocalLinker 保留全部 camera-local 人物假設，再轉成 F3 `Track`，復用 `cross_camera_demo.response` 與 `ServiceTrackDecider`。D124 路徑與未註冊的 run 維持各自入口。

8CAM「人物」回 UNKNOWN 的原因是 `parameters()` 把來源包成整體 `DEMO_DEFAULT`，而 `LinkParameters.from_document` 只收整體與逐項 `APPROVED`；其 `link_min_score`、`link_color_rule`、`link_ambiguity_margin` 也是既有 `DEMO_DEFAULT`。現在只有受控 8CAM demo adapter 明確傳 `allow_demo_default=True`。原來源參數值、狀態與 SHA 不變，未將其升格成 APPROVED；一般推論預設仍拒絕，UNKNOWN／PROPOSED／REJECTED 無論整體或逐項都拒絕。回應明示 `formal_eligible=false`、`parameter_mode=DEMO_DEFAULT`、`identity_verdict=UNCONFIRMED`，保留 graph／parameter／ambiguity 理由和 PARTIAL 狀態。這是工程展示，不是正式追蹤參數驗收。

Agent 預設仍關；開啟時同一 `ServiceTrackDecider` 決定失聯時刻。M1 沿用：不能連到本地軌跡的 SELECT、OWN_BOX、失敗／逾時／不合法回應／超過輪數都交回規則，只有明確 STILL_HERE_OCCLUDED／NOT_VISIBLE 才 WAIT。每次紀錄答案、採用 track_ref、fallback、request SHA、scene_context SHA。重播沿用 decider 快取，不重付費。

手動改選沿用 F3 的 `manual_seed={track_ref,at_us}`；保留多人物與多鏡頭候選，套用時記 `OPERATOR_SELECTION` 與 USER，未知 track_ref／未來 at_us 拒絕。盲區繼續使用 `_blind_for_track` 的 display-only INFERRED 位置推估，沒有將其送入排序或擴大物理導航權限。

8CAM 使用既有校正／graph context 與 hash-checked RGB。B-05 使用既有 synthetic graph 與 hash-checked `read_rgb`；它沒有可用的獨立校正 catalog，故位置、朝向、FOV、地面覆蓋、重疊逐鏡頭明列 UNKNOWN／SCENE_CONTEXT_INCOMPLETE，graph hash 與已知出口配置仍提供；沒有拿 r004 校正填補。未修改 `scene_context` 模組。
