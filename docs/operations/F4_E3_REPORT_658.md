**H1 的範圍是「這個整合」，不是「看圖 Agent 普遍比規則差」。** Agent 在 LOST、AMBIGUOUS（4 m 內有兩人以上）、RECHECK（每 4 s）時被問，平均每段約 105 次（A2 1684 次／16 段），每次被採用的 SELECT 都會重設追蹤器。主要失敗方式有兩個：

## 6. Agent 實際能控制的範圍（Opus #666 要求寫明）

### 8.1 事後診斷（不改判定，§6.0）

這一節只回答「H1／H2／H4 不成立是不是程式錯誤」，數字來自 Opus 裁決（#678 留言 7089025025）。方法：用 PR 的 `e3_f4_score.run_scores` 和釘選評分程式 `acacce39…`，
對 A1、A2 各 48 次執行，逐次找出每個被採用的 SELECT：提問當時 Agent 選的鏡頭在不在 GT 可見集合內、採用後作用中的鏡頭，以及從這次採用到下一次採用之間的錯人 tick。
重建的 A2 錯人秒合計 243.8 s，和 §2 相同。結論：**是這個整合下的 Agent 較差，不是程式錯誤。**

- **錯人秒 +129.8 s 從哪裡來**（K=3 平均後的單組秒數）：
  - 1423 次被採用的 SELECT 裡，約 **478 次（34%）** Agent 選的鏡頭在提問時看不到目標：約 287 次目標完全不在任何畫面（多數變成盲區誤鎖），約 191 次目標在別台鏡頭（變成錯鏡頭）。
  - 鏡頭是 Agent 自己回答的，不經過顯示框推導，所以這部分一定是 Agent 判斷錯。接在這類採用之後的錯人秒是 **164.7 s**，單這一項就超過 B1 的總錯人秒 114.0 s。
  - 可能歸給程式的部分有上限，總量 **73.4 s**：Agent 選對了鏡頭，採用後的結果還是錯。其中錯人 108 次（Agent 在對的鏡頭選錯人，或顯示框推導選到旁邊的人，兩者分不開），作用中鏡頭被「最大框所在鏡頭」換成別台 44 次。
