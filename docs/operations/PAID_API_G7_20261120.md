# G7: guard the provider CLI and display prediction adapter

Issue #651 closes the two paid-call gaps listed in the historical
AGENT_API_WIRING_AUDIT_20261120.md. Work is on codex/feat-api-guard, based
on main 8290f190. It does not enable either paid feature or change the
server budget defaults, and does not wire the display adapter into 8785.

## Dispatch and accounting

`scripts/agent_decision/run_provider.py` retains the existing stage
approval, CallBudget, default dry-run and replay gates. OPENAI live calls,
including an injected provider, now pass through ApiGuard.run before the
provider is invoked. Each retry goes through the guard again. API model
IDs are resolved from the existing params, so prices are looked up by
API model ID rather than config nickname. The normal OpenAI path uses its
actual serialized payload, including system prompt and response schema,
to reserve a conservative byte-length estimate plus overhead. An injected
provider uses the request and the declared prompt estimate. These are
budget estimates, not measured token counts.

The summary includes each guard check's one-call dry-run estimate,
allowed flag, reason and charged estimate. A denial returns a rule fallback
without invoking the provider, reports REFUSED/PARTIAL and exits 2. An old
stage approval in params does not override the server-side guard. Missing
prices, disabled API, token/cost/call caps and exhausted total budget remain
fail-closed. The CLI never auto-enables or raises a configured budget.

`OpenAIPredictionAdapter` accepts an optional server-side guard and otherwise
uses the shared guard. Each actual transport attempt is inside guard.run.
It exposes a one-call dry-run as last_estimate and sends an explicit
max_completion_tokens=400 matching the guard's output reserve. A guard
denial preserves the existing display fallback and reason, with no transport
call and no session attempt consumed. Denied outcomes retain the adapter's
existing per-query caching behavior; retrying that same query does not
silently spend after a configuration change. Successful cache/replay hits
make no new paid call or ledger row.

Valid response usage is charged at the configured price. Missing/malformed
usage and transport failures retain the guard's worst-case reserve charge.
No token count or paid-provider cost is inferred from this engineering test.
Neither ledger nor summary contains prompts, headers, keys or responses;
the existing explicit-key and redaction behavior remains unchanged.

The lower-level OpenAIProvider, other callers' guard placement and W2
transport contracts are unchanged. This is a bounded repair of G7's two
identified entry points, not a new repository-wide transport architecture.
The product spec's U-18/G7 status should be updated by the coordinating
document owner after this PR merges; #653 currently describes main's gap.
