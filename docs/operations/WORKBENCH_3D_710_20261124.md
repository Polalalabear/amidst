## 新版接線與來源邊界

- `app.mjs`的預設路由不變：沒有`?ui=legacy`時仍mount `ui-shell.mjs`。
  新版樓層俯視圖用 `ui-scene3d-panel.mjs`，預設2D，點「3D場景」才建立共享renderer。
  直接重用 `buildScene3dModel`／`mountScene3dView`，沒有複製model或renderer。
  新版仍只經`ctx.legacy`接觸舊DOM；新增panel沒有讀取舊引擎DOM，舊版保留。
- `display_estimate`仍只來自既有track response→`buildCoreTrackingViewModel`／`projectTopdown`。
  2D估計點與半徑只使用 `display_position.status=CALIBRATED_STATIC` 且有限 `xy_m` 的鏡頭作公尺座標；
  示意座標不能錨定估計。圖框只含鏡頭與既有曲線，估計與半徑不影響縮放；+y 在 SVG 上方。
  出界不畫點、不夾邊，顯示「估計位置超出圖面」。3D直接用共享scene model的公尺座標與不確定範圍。
  作用中鏡頭使用既有 `cam is-active` 節點與 accent fill；不另畫 `.here`／here-ring 圈，也不把鏡頭當人。
  有值標「系統估計（推論）」；未知半徑不捏造數字；2D圓形明示未考慮牆。
- UNKNOWN不畫估計點／估計範圍，清掉上一筆位置；文字直接重用#709 `estimateUnknownText`，
  保留5個原因的中文與原碼，未知新碼原樣顯示。舊backend沒欄位顯示「沒有系統估計」。
  身分維持未確認，不新增身分或通行權限；只改顯示，不把投影回送推論。
- 資產／renderer失敗顯示「3D資產不存在」並回2D；catalog缺少當前run鏡頭也不顯示其他場景的3D。
  切run、離開case2、pagehide及UI destroy都釋放view；延遲ready／reject不會復活舊run。
  未變的幾何不因clock-only tick重建，HUD時鐘照常更新。
- `scene3d-view.mjs`釋放動態geometry／material、每個view自己的場景material、controls、renderer與GL context。
  靜態geometry／載入結果仍屬既有頁面共用asset cache，不銷毀其他view共用來源。
  重新mount可重用cache，不重新複製LOCAL檔案或重渲染影片。

## 範圍第5點：t=1s HUD與NO_SIGHTING

程式根因：舊`core-tracking-view.mjs`的3D HUD只把GAP／LOST分成「盲區」，其餘一律寫「追蹤中」。
`NO_SIGHTING`在`buildCoreTrackingViewModel`中是segmentKind UNKNOWN，因此落入錯誤的else。
本輪把狀態文案集中在共享 `scene3dStateText`：

| 來源 | 顯示 |
| --- | --- |
| response.status = NO_SIGHTING | 目前沒有觀測紀錄 |
| ON_CAMERA | 追蹤中 |
| GAP | 盲區（未見目標） |
| LOST | 目標遺失 |
| PENDING | 目標尚未出現 |
| 其他／缺失 | 追蹤狀態 UNKNOWN |

新panel與原3D HUD都讀共享model的stateText，沒有兩份狀態推測。
Node測試分別直接mount新版前台及原core view，驗t=1s／NO_SIGHTING不寫「追蹤中」。
沒有讀取或修改該截圖／任何影片／GT。

**結論**：正式啟動並非必然讀不到。若從pin所在checkout啟動，資產與three的resolved檔案在該REPO或owned root內，

該目錄通常在clone的REPO與owned package外，read_bytes會被guard拒絕而回403；
若clone自己的local存在但沒assets，則回404。環境覆寫若仍指向外部檔案，也不會自動繞過guard。
不能把#623／#709的clone臨時複製手法當作正式啟動已通過。

本輪沒有改I/O guard、環境或啟動器，沒有複製scene.glb／calibration／three、沒有讀大型資產。

## #714 複審修正：Opus 裁決 1–6／Sonnet 兩阻擋項

裁決：https://github.com/Polalalabear/amidst/pull/714#issuecomment-7125926619 。原 head `2612dec4` 的
座標框、未來估計與 B-05 面板問題已在同分支補修；沒有 rebase、force 或改 real-e2e。

1. `camera_map.cameras[].display_position` 是 2D 公尺錨點的唯一來源；必須 CALIBRATED_STATIC 且 xy_m 有效。
   layout 不作 authority，NODE_GRAPH 的已校正鏡頭仍可用；METRIC_STATIC 同樣逐鏡頭驗證。
   不混入裸 displayPositions 示意座標；舊相容示意輸入仍可畫節點但不疊公尺估計，只留文字。
   `display_note` 原文保留在 2D 圖下，不自行改稱校正圖。
2. 鏡頭、既有盲區曲線與估計共用等比例投影；SVG y 翻轉，+y 向上，對齊 3D `(x,h,-y)`。
   Node 驗證 +y 較大的鏡頭在上方、曲線端點與估計點重合；實際 2D／3D 方向截圖待 gate 後。
3. 範圍固定取鏡頭與既有曲線的 min/max，不含估計與 uncertainty。
   估計中心超出固定範圍時 2D 不畫點／圈、不夾邊；摘要寫「估計位置超出圖面」。
   3D 仍可畫有效時間的原始公尺座標，不受 2D 圖框裁切。
4. 共用 `scene3d-model.mjs::readEstimate` 檢查 `last_observed_us`、`currentTUs` 與時鐘。
   只有有限非負時間且 `currentTUs >= last_observed_us`、`source_clock_id` 等於目前 run 時鐘時可畫。
   run 時鐘由 activeRun.clock_mapping.clock_id（相容 clock_id）經 store、seek／layout／speed、
   新舊 view fallback 入口傳入。缺值不改用 as_of_us；不符一律 UNKNOWN、清掉點／半徑／trail。
   2D 投影、新舊 3D、HUD／摘要與 legend 共用同一判斷及原因文字；沒有修改 backend contract。
   前端原因為 LAST_OBSERVED_US_INVALID、CURRENT_TIME_INVALID、SOURCE_CLOCK_MISSING、RUN_CLOCK_MISSING、
   SOURCE_CLOCK_MISMATCH、ESTIMATE_IN_FUTURE（不新增到 backend 的五種 reason）。
   測試反轉 tUs=1e6／as_of_us=5e6 的未來點斷言，另驗時間剛好相等可畫、倒退 seek 清除舊圈。
   現有後端最後觀測接近 A4 49.8s／B4 41.8s，因此大部分播放期間 UNKNOWN 是預期，不用未來值補畫。
5. `floorPlan.available` 只由可用鏡頭 nodes 決定；只有 estimate 不能讓圖面可用。
   沒鏡頭位置則整個 `#ui-floorplan` hidden，包含 B-05 有有效 display_estimate 的 Node DOM 案例。
   沒有修改 `tests/browser/ui-redesign/real-e2e.mjs` 或執行服務／瀏覽器。
6. 作用中鏡頭沿用 `cam is-active`，既有 CSS accent fill 不變；Node DOM 斷言鎖定此標示。
   不新增代表目前人物位置的圈；系統估計點仍須通過上述空間與時間判斷。
