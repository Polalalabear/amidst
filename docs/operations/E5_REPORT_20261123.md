## 6. 偏差與限制

1. **AO-L 先延後、後補跑**：Opus 裁決（#694，D361）規定，N2（EXPIRED 答案的排序不能進 `rows[].ranking`）修好並審查過之前不能跑 AO-L。AO 報告撰寫時 H8d 是「未執行」；N2 修正（#696，`24c2dce9`）合併後，AO-L 已在 2026-11-24 執行，結果見 §9。AO（offline）不會產生 EXPIRED，所以 N2 未修**不影響** AO、H8a、H8b、H8c。
2. **N4（`CALL_CAP_REACHED` 讀法）**：依 Opus 裁決，「達到上限」指呼叫數等於上限的那個 tick，每段最多一筆。報告寫成「達到呼叫上限的段數」，不是「被擋下的提問數」。這次資料為 0 段。
3. **N5（`calls[].tick`）**：`calls[].tick` 是答案的生效 tick，提問 tick 另存在 `ask_tick`；段尾在途呼叫的 `tick` 仍是提問 tick。契約未定義，`run_e5` 與評分包裝程式讀得動。
4. **N3**：`URLError(timeout)` 可能被歸為 `PROVIDER_ERROR` 而不是 `PROVIDER_TIMEOUT`，兩者都算 provider 錯誤率；這次兩者皆為 0，沒有影響。
5. **規則依附**（預登 §0）：AO 的目標種子取自規則第一次 ACQUIRE，所以 H8 測不到「Agent 自己找到第一個目標」的能力。
6. **B1 沿用 E3**（`runs-final-9`、`runs-final-665`）；#676 的規則修正未合併，B1 固定在 E3 版本。
7. 評分前沒有看任何 AO 分數；一次評分，沒有任何修改或重跑，所以沒有「兩版」報告。
8. 未統計項目：中性追蹤器延續 tick 數；逐段費用（只有行程層級的帳本，未依段切分）。
