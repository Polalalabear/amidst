## First two cases for F1 format validation

The initial checkpoint delivers E3-A3 (similar clothing crossing) and E3-B1
(two 4.8 s blind gaps): 78.8 s, 10 declared decision opportunities, 3,152
indexed camera frames. Each is `live-ab.case.v1`, recorded through the unmodified
LIVE A page with N6 GLBs and all eight cameras. The full input stream and
Chrome expected states replay twice, in addition to the original recording.

The evaluation catalog is `configs/evaluation/e3_live_cases_v1.json`.
Its initial status is a two-case format handoff; the remaining cases are still
in production. This is not an E3 result, preregistration or rule/Agent comparison.

Set `E3_ROOT` to the scratch clone's `local/evidence/e3-652-20261122`.
All raw outputs remain LOCAL; the pinned demo checkout is untouched. The F1
reader can consume, for each catalog case:

| Input | Path below E3_ROOT | Existing format / role |
| --- | --- | --- |
| Recorded renderer inputs | `<id>.case.json` | `live-ab.case.v1`; A-private, never inference |
| Camera images | `rgb/<id>/<camera>/<frame>.png` | 320x180 RGB, 5 Hz, no labels/GT/overlays |
| Shared RGB descriptor | `rgb/<id>/rgb_index.json` | `controlled-scene.rgb-index.v1`; paths, clocks, hashes |
| Detection index | `indexes/<id>/detection_index.json` | `q-demo.detection-index.v1` |
| Detection rows | `indexes/<id>/detection_index.records.jsonl` | Existing detection-record fields, bbox/score/HSV |
| Scoring truth | `gt/<id>.a-log.json` | `live-ab.a-log.v1`; actors[].xy/gt_visible, separate scoring file |

Agent and rule arms must read the **same PNG bytes and frozen detection index**.
Do not redetect in each arm. Camera JPEGs from the actual A capture are retained
under `pixels/`; the shared PNGs preserve their decoded RGB exactly. The index
binds PNG hashes, the descriptor retains each source JPEG hash, and the manifest
binds all files. There is one guard capture at the case endpoint; the index uses
only `[0, duration)` so its source grid has exactly duration * 5 samples/camera.

The production `JsonRunStore.load_detection_index` loads both sample indexes;
the verification script checks all image pins, complete eight-camera grids,
clock alignment, GT separation and all three browser state sequences. The
capture harness uses a pixel sink, whose IDLE response is **not tracking output**.
Real RT-DETR runs offline on those captured images with the existing official
strict R18 weight loader, letterbox preprocessing, MPS and score floor 0.05.
Index HSV uses the existing upper-HSV format. LIVE B1's existing area-ratio HSV
(.2) is replayed separately when freezing C's baseline, without relabelling it
as the index's eligible-pixel ratio (.3).

## Reproduction and verification

Use the existing Python environment through uv. Supply the existing
`E3_PYTHON`, `RUNTIME_DEPS`, `LIVE_ASSETS` and `MODEL_ROOT` from your local setup;
no source assets are copied or overwritten. Install the frontend lockfile with
`npm ci --ignore-scripts` in `frontend/live-mode`. Use a new output directory
when rebuilding; keep the frozen corpus for F4.

```sh
node scripts/evaluation/e3_cases/generate.mjs "$E3_ROOT" "$LIVE_ASSETS"
node scripts/evaluation/e3_cases/record.mjs "$E3_ROOT" "$LIVE_ASSETS"
node scripts/evaluation/e3_cases/annotations.mjs "$E3_ROOT"
PYTHONPATH="src:$RUNTIME_DEPS" uv run --no-project --python "$E3_PYTHON" python -B scripts/evaluation/e3_cases/index.py --root "$E3_ROOT" --models "$MODEL_ROOT" --cases E3-A3 E3-B1
PYTHONPATH=src uv run --no-project --python "$E3_PYTHON" python -B scripts/evaluation/e3_cases/verify.py --root "$E3_ROOT" --cases E3-A3 E3-B1
node --test frontend/live-mode/test/recording.test.mjs
uv run --no-project --python "$E3_PYTHON" python -B -m pytest tests/evaluation/test_e3_cases.py tests/q1q5/test_detection_index.py -o addopts= -q -p no:cacheprovider
git diff --check
```

The browser is headless and the private loopback service closes in `finally`.
Wall pacing is accelerated, but each production step remains 0.05 s behind the
capture barrier. Initial Node-generated inputs omit Node's expected snapshots
on the first Chrome capture: Node and Chrome can differ in their last floating
point bit. Formal expected states come from Chrome and are checked on the two
complete Chrome replays. Cross-engine bitwise identity is not claimed.

## Boundaries and remaining work

GT is only renderer/evaluation input. Runtime input allowlists include RGB,
clock, camera calibration and the pixel-derived index; never the case's actor,
expected states, route, A logs or scoring catalog. Visibility is the existing
static-wall body-point-ray proxy, not a segmentation mask or person occlusion
truth. Identity is UNCONFIRMED and physical navigation is UNKNOWN.

Five decision opportunities per clip describe correlated phases of authored
scripts. They are not five independent trials or observed model decisions.
F1 owns the scoring criteria and F4 owns the paired model experiments. No paid
API request or Blender render is part of this production; captures are LIVE
WebGL with unchanged original GLBs. Detector output/JPEG bytes/latency are not
claimed deterministic; the frozen output pins provide the shared F4 input.

C will use the merged B1 rule, with `GRAPH_DISTANCE_FALLBACK` if it has no
ranked camera list. Undirected graph hop distance matches CameraScheduler;
ties use camera ID as reproducible representation, current camera excluded.
CAM_ENTRY is absent from graph v3 and stays NOT_IN_CANDIDATES. F2 is not used
to construct these challenges. Final C records must show two clips outside the
original top three before the full catalog is marked formal.
