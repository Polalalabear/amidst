# Demo 腳本兼驗收清單 v1（大問題 A · #445）

對應 [#445](https://github.com/Polalalabear/amidst/issues/445) 勾選清單的「W-A21 兩核心 demo 腳本與操作說明（原 #463）」，也是最後一項「使用者在 Mac 逐項驗收」的操作表。

- 用途：展示時照著點，同時逐項打勾驗收。畫面定版後只需微調文字。
- 畫面版本：新 UI（#487，分支 `claude/ui-redesign-v1`）。服務跑在 `http://127.0.0.1:8785`。
- 這是工程展示的驗收：不確認人物身分，也不證明實際走得通；畫面上的 UNKNOWN、MISSING 是故意保留的，不是壞掉。
- 勾選方式：把 `- [ ]` 改成 `- [x]`，或印出來用筆勾。

## 0. 啟動

重開機後，在終端機貼上這一行（只要開一份；已經開著就不用再開）：

```bash
/Users/polalabear/amidst-demo-20261104/start_445_demo.command
```

這個資料夾要先切到 `claude/ui-redesign-v1`（Codex 已處理；若不確定，請問 Codex）。

### 確認服務已經起來

- [ ] 終端機出現伺服器啟動訊息、沒有停在錯誤上，視窗不要關。
- [ ] 瀏覽器開 <http://127.0.0.1:8785/workbench-v2/?run=B-05>，看到黑底封面和「Amidst」大字。
- [ ] 或在另一個終端機貼：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8785/workbench-v2/
```

  看到 `200` 就是起來了；看到 `000` 或連不上，就是還沒開（見第 4 節）。

> 建議用 Chrome，視窗放大到桌機大小（1440×900 左右）。

### D139 後的畫面約定（以下步驟都依此）

- **展示模式（前台預設開）**：畫面只寫白話。技術標籤（自動種子、DEMO_DEFAULT、GRAPH_NOT_APPROVED、ASSOCIATION_IDENTITY_UNCONFIRMED、UNKNOWN、ACTUAL_BLENDER、D124 等）收進「ⓘ」，滑鼠移上去（或用 Tab 聚焦）才顯示。狀態白話對照：已觀測＝OBSERVED、推測＝INFERRED、此時段沒有畫面＝MISSING、已跟丟＝LOST、無法判定＝UNKNOWN；內部仍分四種，沒有把推測當成已觀測。後台照舊完整顯示，也可在後台設定關掉展示模式，或網址加 `?present=0` 看完整標籤。
- **時段一律是具體時間**，格式「13:00:00～13:05:00」，不會出現「留空」「現在」。
- **播放速度是下拉選單**（0.5×／1×／1.5×／2×），沒有「設定 1×」文字；只有測到實際倍速落後時才在旁邊顯示「實際 N×」。時間軸只有一條。
- **頂列的模式切換**（查找｜追蹤｜查看）：取代原本的「追蹤新目標…」，任何頁面都能一鍵換模式；查詢窗改用左上漢堡鈕開關。
- **左上「Amidst」**（前台各頁和後台都一樣）：回到前台主頁（封面開著就回封面，否則依「預設進入」設定）。
- 頁面分頁圖示（favicon）已內建，瀏覽器主控台不再有 `/favicon.ico` 403。

## 1. 逐步腳本

三個事件的網址只差 `run=`：`B-05`、`A4-1`、`B4-1`。建議展示順序：先用 **B-05**（最簡單）走完一輪，再用 **A4-1** 或 **B4-1** 秀盲區。

網址前綴統一是 `http://127.0.0.1:8785/workbench-v2/`。

### 步驟 1　封面

打開 <http://127.0.0.1:8785/workbench-v2/?run=B-05>

- 點哪裡：先不要點，等約半秒讓動畫跑完。
- 預期看到：
  - 小標「多鏡頭查找與追蹤」、大標「Amidst」、副標「Agentic 驅動之智慧監控數位孿生系統」。
  - 一行說明，下方「進入系統 →」按鈕。右上有「後台」。
- 可以講：「這是一套多鏡頭查找與追蹤的輔助系統，輸入時間、地點或特徵，它幫你找出畫面。」
- 驗收：
  - [ ] 副標文字正確（含「Agentic 驅動之智慧監控數位孿生系統」）。
  - [ ] 動畫不拖（約半秒內結束）。

### 步驟 2　三選一

- 點哪裡：「進入系統 →」。
- 預期看到：標題「要做什麼？」，三張卡：case 1 查找、case 2 追蹤、case 3 查看；左下「← 回封面」。
- 可以講：「這個系統有三件事：找、追、看。」
- 驗收：
  - [ ] 三張卡都在，文字看得懂。
  - [ ] 點「← 回封面」能回去，再進一次。

### 步驟 3　case 1 查找（B-05）

- 點哪裡：「case 1 查找」。畫面會有「查找」查詢窗（沒開時按「開啟查詢窗」）。
- 輸入：
  1. 特徵：點「人物」。（地點或特徵至少填一個；特徵很多時只有特徵清單那一區可以捲動。）
  2. 開始時間：`13:00:00`
  3. 結束時間：`13:00:08`（欄位預設已填整段錄影的時間）
  4. 點「開始查找」。按鈕固定在查詢窗底部，一打開就點得到，不會被捲走。
- 預期看到：
  - 先有進度（標明「進度為示意」），然後結果牆出現 **2 個畫面**（B-05 有 2 台鏡頭）。
  - 每張圖是「來源綁定 RGB」，不是空白；卡片上有狀態標籤，並標示「身分未確認」。
  - 點任一張可放大，按 ◀ ▶ 切換，按 Esc 關閉。
- 可以講：「時間範圍一定要填，地點或特徵至少一個；結果是拍到目標的鏡頭畫面。」
- 驗收：
  - [ ] 結果牆 2 張，圖片都有顯示。
  - [ ] 放大、上一張／下一張、Esc 關閉都正常。
  - [ ] 把開始或結束時間清空按送出，會被擋下並說明要填時間。
  - [ ] 查詢窗按 Esc 或再按左上漢堡鈕會收起，收起後不能點到裡面的東西；再按漢堡鈕可重新打開。
  - [ ] 時間填了但地點與特徵都不選，也會被擋下。

#### 步驟 3b　case 1 查找（r005：101 教室、筆電）

- 預期看到：結果牆列出 101 教室（或有筆電）的鏡頭畫面。物件是模型偵測、再加人工覆蓋標註；地點目錄沒就緒時會顯示「地點資料尚未就緒」。

### 步驟 4　case 2 追蹤：單畫面

先看 B-05，再用 A4-1 重做一次（A4-1：開始 `14:00:00`；B4-1：開始 `14:10:00`）。

- 點哪裡：回封面或三選一 → 「case 2 追蹤」。查詢窗標題是「追蹤新目標」。
- 輸入：特徵點「人物」；開始時間填 `13:00:00`（B-05）；結束時間看欄位提示「到錄影結尾（HH:MM:SS）」，不改就是追蹤到錄影結尾，也可以自己填。兩格都留空＝整段錄影（開始是錄影起點，結束是錄影結尾）；點「開始追蹤」。
- 預期看到：
  - 先有「在 N 台鏡頭中尋找目標…」的進度；鎖定後標題變成「人物 · 已鎖定」。
  - 標題下方有「查詢時段 13:00:00～13:05:00」（實際查詢的時間，不是空白）。
  - 中間是單畫面；下方有播放列：播放／暫停、速度下拉選單（0.5×／1×／1.5×／2×）。時間軸只有一條：「鏡頭時間軸」（A → 盲區 → B → 已跟丟），點或拖它就能跳到該時間。
  - 右邊有「樓層俯視圖」、「追蹤紀錄」。追蹤紀錄會把「同一鏡頭 1 秒內離開又出現」的短暫抖動合併成一筆，並寫「已合併 N 次短暫離開」；原始紀錄在後台。
  - 追蹤中會看到「停止追蹤」按鈕。
- 操作：按播放，等到人走出一台鏡頭。
- 預期：畫面會**自動切到下一台鏡頭**，並標示「↳ 從 … 切換」。
- 可以講：「鎖定之後，鏡頭會自動切換，一直追到跟丟為止。」
- 驗收：
  - [ ] 鎖定成功、單畫面有圖。
  - [ ] 播放後自動切鏡頭（至少切一次）。
  - [ ] 速度下拉選單選 0.5×、1×、1.5×、2× 各一次，選項有切換；畫面上沒有「設定 1×」字樣。
  - [ ] 時間軸只有一條；追蹤紀錄不再出現同一鏡頭「出現於／離開畫面」快速交替。
  - [ ] 技術標籤收在「ⓘ」，滑過才看到；畫面上沒有 GRAPH_NOT_APPROVED、UNKNOWN 等英文代碼。
  - [ ] 兩格時間都清空再按「開始追蹤」，結果頁顯示「查詢時段」是整段錄影，不是 14:00:00～14:00:00，也沒有「時間窗內無觀測紀錄」。
  - [ ] 跟不上時會自動降速並顯示「實際 N×」（有看到就勾；沒看到不算失敗）。
  - [ ] 底部播放列固定在視窗最下面，內容多時只捲動中間內容。

### 步驟 5　case 2 追蹤：多畫面

- 預期看到：多張同時間的鏡頭畫面（所有找到目標的鏡頭），每張都有圖。按播放，時間會往前走。

- 驗收：
  - [ ] 多張畫面都有圖，沒有空白或壞圖。
  - [ ] 播放時時間推進，畫面跟著更新。
  - [ ] 切回「單畫面」正常。
  - [ ] 底部播放列仍在視窗最下面。

### 步驟 6　case 2 追蹤：盲區與俯視圖

盲區是目標暫時不在任何鏡頭裡的時段。

- 做法（正式操作）：在單畫面把時間軸拖到盲區時刻；開啟查詢窗，把時間清空（整段錄影），按「開始追蹤」，再把時間軸拖回該時刻。
- 快速做法（直接開網址）：
  - A4-1：<http://127.0.0.1:8785/workbench-v2/?run=A4-1&screen=blind&as_of_us=9400000>
  - B4-1：<http://127.0.0.1:8785/workbench-v2/?run=B4-1&screen=blind&as_of_us=2100000>
  - B-05（看「無法預測」的樣子）：<http://127.0.0.1:8785/workbench-v2/?run=B-05&screen=blind&as_of_us=3000000>
- 預期看到：
  - 沒有當下觀測時，狀態可為盲區或 LOST；LOST 顯示「已跟丟」，不能因有預測就改成已觀察。
  - 「樓層俯視圖」上，**實線＝看到過的路線，虛線＝推測的路線**。
  - A4-1：虛線存在，標「推測路線 · 信心低」。B4-1：信心未知，虛線畫成示意。
  - 目標重新出現後（播放頭走過盲區），虛線終點有圈，下方寫「已由 X 鏡頭於 HH:MM:SS 觀測到」，標籤改成「兩端已觀測，中段為推測」。
  - B-05：沒有虛線，寫「無法預測」（沒有鏡頭位置資料，不畫曲線）；ⓘ 裡才有 UNKNOWN。
- 可以講：「看不到的時候不假裝知道；系統畫出可能的方向，並標明這只是推測。」
- 驗收：
  - [ ] A4-1 有虛線，標「推測路線 · 信心低」；沒有當下觀測時保留「推測」「已跟丟」狀態，不改成已觀測。
  - [ ] 目標重新出現後虛線終點寫「已由 X 鏡頭於 HH:MM:SS 觀測到」，標籤「兩端已觀測，中段為推測」。
  - [ ] B4-1 有虛線（示意），信心標為未知。
  - [ ] B-05 沒有虛線，並明確寫「無法預測」，不是空白。
  - [ ] 沒有任何畫面把推測當成已看到。

### 步驟 7　case 2：停止前端追蹤、確認自動種子限制（D137）

- 點「停止追蹤」：只停止前端播放並清掉本次追蹤顯示，按鈕變灰；不呼叫後端停止、不改契約。暫停則保留目前追蹤畫面，兩者不同。
- 「改選目標」按鈕保留但停用，旁邊必須出現：「追蹤起點由系統自動選擇，目前還不能手動改選目標」（D139 把原本的「自動種子」說法改成白話；自動種子的標示收在 ⓘ）。這是 D137 核定行為，不是假裝已支援手動種子。
- 要換查詢，點「回查詢窗重新輸入特徵」或上方「❯ 追蹤新目標…」，重新輸入並開始追蹤。手動指定種子的契約擴充留在大問題 D #489，驗收後依新契約處理。
- 驗收：
  - [ ] 停止後不再播放、追蹤影像消失、來源不變，沒有後端 stop 呼叫。
  - [ ] 「改選目標」停用且上列說明完整出現（依 D137，此狀態不算驗收失敗）。
  - [ ] 回查詢窗重新送出後可以再次追蹤。

### 步驟 8　case 3 查看

- 點哪裡：回三選一 → 「case 3 查看」。
- 預期看到：事件名稱的下拉選單（上方「資料來源」，切換事件）和頁內事件按鈕（B-05、A4-1、B4-1）、整面監控牆；牆上鏡頭數：B-05＝2、A4-1＝4、B4-1＝5，且都有圖。
- 操作：用上方下拉選單（或事件按鈕）切到另一個事件（例如在 A4-1 時選 B4-1），網址的 `run=` 會改變，牆重新載入。
- 直接開網址：
  - B-05：<http://127.0.0.1:8785/workbench-v2/?run=B-05&screen=case3>
  - A4-1：<http://127.0.0.1:8785/workbench-v2/?run=A4-1&screen=case3>
  - B4-1：<http://127.0.0.1:8785/workbench-v2/?run=B4-1&screen=case3>
- 預期補充：下方註記只寫事件名稱和「身分未確認」；資料來源、「物理通行與碰撞 UNKNOWN」收在 ⓘ。播放列顯示的時間是具體時間（例如 14:00:12 / 14:00:50）。
- 可以講：「查看模式是整段事件回放，所有鏡頭同時看。」
- 驗收：
  - [ ] 三個事件的鏡頭數對（2／4／5），都有圖。
  - [ ] 下拉選單和事件按鈕都能切換事件，沒有灰掉的（未啟動）選項。
  - [ ] 速度下拉選單 0.5×／1×／1.5×／2× 可用。

### 步驟 9　後台：概況

- 點哪裡：任一頁右上的「後台」，或直接開 <http://127.0.0.1:8785/workbench-v2/admin.html>。
- 預期看到：「系統概況」。有鏡頭數、目前追蹤、最近事件、涵蓋區域、偵測數據、各鏡頭偵測數、時間軸、事件流；另有「鏡頭播放」「紀錄」分頁。
- 偵測數據中，有些格子顯示「尚未量測」，這是正常的（見第 5 節）。
- 可以講：「後台只顯示真的量過的數字；沒量過的老實寫尚未量測。」
- 驗收：
  - [ ] 概況頁打得開，鏡頭數正確。
  - [ ] 未停止時「目前追蹤」有內容；停止後不再冒稱仍追蹤，「最近事件」保留停止記錄。
  - [ ] 沒量測的格子寫「尚未量測」，不是 0 也不是假數字。

### 步驟 10　後台：設定

- 點哪裡：後台的「設定」分頁。

## 5. 已知缺口（以下都是已知項目，不算驗收失敗）

1. **D131 驗收規則**：底部列、結果牆、legacy 顏色、timer 與 DOM／瀏覽器 gate 都必須通過；任何可修問題仍算失敗，修正後重跑。本文件不能豁免 P2／P3。
2. **後台「尚未量測」的數字**，共三個，目前沒有量測來源：
   - 偵測速度（張／秒）
   - 鏡頭切換 P90（秒）
   - Agent 回應（秒）

   另外「物件偵測」顯示 UNKNOWN（來源沒宣告偵測器名稱）。已有本機量測的：首次鎖定、查找耗時；來源有宣告才有數字的：缺幀率、盲區占比、索引狀態。沒做過對應操作時，這幾格也可能顯示尚未量測。
3. 「各鏡頭偵測數」是最近一次查找的相符影格數，不是整體偵測總數。
4. B-05 的盲區曲線是 UNKNOWN；它不是壞掉。
5. 進度條是示意，不代表實際完成比例（畫面上有註明）。
6. 沒有指令面板（`/`、`Cmd+K`）；倍速是 0.5／1／1.5／2。
7. 追蹤、查找用的是已存的來源資料，不是即時推論；身分、物理通行、真機顯示時間都沒有正式量測。
8. **特徵分組**（本場景偵測到的類別在上、其他 COCO 類別調淡收合在下）尚未提供：現有 API 沒有每類別偵測數，要等 Codex 補欄位；目前特徵清單是完整的 80 類。
