## 問題、根本原因與修法（v2）

**現象：** 本機模型的 DP1／DP3 從未到達模型（見上）。NL 走另一個 client，不受影響。

**根本原因（有證據的部分與推論分開）：**

- 證據：`wp5_runner.live_context` 對 DP 題型用 `OllamaProvider(...).call`，對 NL 用 `OllamaNlClient`，兩者送給 Ollama `/api/chat` 的 `format` 不同。DP 的 `format` 是 `agent_providers.RESPONSE_SCHEMA`，它是從契約 schema 裡**單獨切出來的 `$defs/response`**，其中 `candidate_id` 還是 `{"$ref": "#/$defs/opaque_id"}`，但旁邊沒有 `$defs`，所以 `$ref` 懸空；同一份 schema 還有 `if/then/else/not`、`uniqueItems`（Ollama 的 JSON-schema→grammar 編譯器不支援）。NL 的 `format` 是自包含的，沒有 `$ref`。回傳列的特徵（`attempt_outcomes=["PROVIDER_UNAVAILABLE"]`、`steps=1`、約 35 ms、`prompt_tokens=None`）符合「Ollama 收到請求後立刻回非 2xx／非 5xx 的錯誤」：`OllamaProvider.call` 把 HTTP 4xx 對應成 `UNAVAILABLE`，`decide()` 對 `UNAVAILABLE` 不重試、直接退回規則。
- 推論（**沒有在真的 Ollama 上重現**：本機沒有 Ollama 與模型，v1 回傳檔也沒記 HTTP 狀態或錯誤內容）：Ollama 以 HTTP 400（無法解析 `$ref`）拒絕。單元測試的假 Ollama 照這個行為（`format` 含 `$ref` 就回 400）。**使用者在 L4 上重跑時，筆記本會在跑題組前先送一題 DP1 並印出 HTTP 狀態與錯誤內容**；若修法沒有解決，會立刻停下並印出真正原因，不會再白跑一輪。
- 為什麼測試沒抓到：既有測試都用 fake transport、而且只比對「送出的 `format` 等於契約切片」，沒有一個測試走完整的 runner→DP 路徑，也沒有任何檢查在「整個題型 100% 退回規則」時報錯，所以 v1 把 100% fallback 當成正常結果輸出。

**修法：**

1. `OllamaProvider` 送出前用 `ollama_format_schema()`：把 `$ref` 內嵌、拿掉 Ollama 不支援的關鍵字（`if/then/else/not/uniqueItems/$defs/…`）。這些限制本來就由 `agent_decision.validate_response` 在回應端檢查，所以不降低把關。
2. `OllamaProvider.last_error` 記錄最近一次失敗的 HTTP 狀態與內容前 300 字；runner 把它寫進該列 `provider_error`，並在 `summary.json` 的 `provider_error_sample` 裡留一個樣本。
3. 守門：`summary.json` 新增 `status`（`OK`／`FAILED`）、`failures`、`warnings`。DP1／DP3 任一模型 × 題型 100% `PROVIDER_UNAVAILABLE` → `FAILED`，`summary.md` 開頭標「RUN FAILED」，`MANIFEST.json` 記 `status`，runner 回傳碼 3 並在 stderr 印原因；fallback 比例超過 20%（`MAX_FALLBACK_RATE`）但未全數 → `warnings`。
4. 筆記本（新增 `src/amidst/agent_eval/wp5_colab_checks.py`，標準庫，隨包）：每個模型暖機後跑 `ollama ps` 與 `nvidia-smi`，**不是 100% GPU 就停**；送一題 DP1 確認有模型回應，否則紅字印出 HTTP 狀態與內容並停；跑完逐題型印 fallback 比例，超過 20% 紅字；`ENV.json` 新增 `ollama_ps`（含 `ollama ps` 原文與 GPU 百分比）、`dp1_probe`、`fallback_report`、`run_status`（`OK`／`WARN`／`FAILED`）；有題型從未呼叫到模型時整份標 FAILED 並在最後一格 `SystemExit`。Windows 的 `run.py` 同樣處理回傳碼 3。
5. Colab 的「沒使用到 GPU」提示：它只看筆記本自己的 Python 程序，而它不用 CUDA；GPU 是另一個 `ollama serve` 程序在用。要看 `ollama ps`（`100% GPU`）和 `nvidia-smi`，筆記本開頭與步驟 6 都這樣說明。

**測試（見下方驗證）：** `tests/q1q5/test_wp5_local_provider.py` 用嚴格的假 Ollama（`format` 含 `$ref` 就 400）驗證 `colab_l4` 與 `windows` 兩個 arm 下 DP1／DP3 成功時 `decision_source=AGENT`（`ad.decide` 的「模型回答」值）、NL 是 `LOCAL`，全部有 token；DP 題型全 400 時 runner 回傳 3、`status=FAILED`；部分 fallback 只警告。
