# D92 Q1／Q2／Q3 response v2 與解析收據執行契約

來源：[D92](https://github.com/Polalalabear/amidst/issues/93#issuecomment-6434464633)、[D92-B](https://github.com/Polalalabear/amidst/issues/93#issuecomment-6434474506)。主契約 #260 的 D92 補充優先；本文件為 I3 的實作介面。新產品只產 response v2，request／LLM intermediate／decision-record／link-record 的版本保持各自既有版本；link-record 原生維持 v2。

## 回應版本與來源

- 新 schema：q-demo.q1-response.v2、q-demo.q2-response.v2、q-demo.q3-parse-response.v2。各自獨立 schema，resolved_scope 的全部鍵仍必填且 additionalProperties=false。
- 相較 rc4 的 18 鍵 scope 只加 time_range_source。封閉值：EXPLICIT_SOURCE、EXPLICIT_WALL、DEFAULT_SELECTED_RUN、null。沒有 time_range_reason。只有尚未形成 requested_time 時為 null；明示時間合法但超出 run，仍保留 EXPLICIT 來源。
- 完全無時間、語法已解析、request.context.run_ids 恰一個已選註冊 run、clock scope/hash 正確時，Q3 取 `[0,source_duration_us)`。t0_us 為牆鐘對應錨點。部分／無效時間、日期但缺時間、相對時間、未知條件、缺 mapping、多 run 不套預設。正式題須明寫核定時間，不使用整段預設。
- 跟著／追蹤／去了哪裡等追蹤動詞才形成 Q2；單獨紅色的人、那個人、找紅衣人形成 Q1。互斥指令或跟著車不執行 Q2。LLM 不得覆寫封閉規則的 intent／時間。
- D80 preimage 原封不動：`{request:N(9鍵),bindings:{index,aliases,parameters,clock}}`；來源只進 output hash 與 parse receipt。相同查詢條件的 Q1 query_id／query_sha256 相同。

## 從 Q3 執行與錄製

直接 Q1／Q2 domain request 仍為 v1，時間須明示；整段來源範圍本身不代表 parser default。
若 consumer 要執行 Q3 的 structured_query 並保留時間來源，須交 Q3 response.output_sha256 作為 **API envelope 的 parse_response_ref**，不塞進 domain request，不加進 D80 preimage：

```json
{"request":"<原 structured_query 物件>","parse_response_ref":"<原 Q3 output_sha256>"}
```

上述 envelope 適用 q1_camera_search、q2_session、q2_seed_candidates。q2_start_session／q2_select_seed 原 envelope 仍帶 selected_observation_id，只另帶 parse_response_ref。
server 只接受同 session 已保存的 PARSED v2 收據，structured_query 必須與 request 完全一致；Q1 只有分頁 cursor 可變，仍驗原 query lineage。缺／外來／改條件的收據拒絕；無收據的直接明示 request 不偽稱 DEFAULT_SELECTED_RUN。

Q2 執行 session_id 在有 parse receipt 時另綁定其 ref，防止相同 domain request 的直接執行與解析來源命中同一個 response cache；這不改 Q1 query preimage 或任何 domain request。輸出 bundle 保存 parse_receipt_ref／原 parse_response，輸入 pins、回應與 journals 都原樣保存。API playback 驗原 hash／父收據；kernel replay 使用保存的來源與 ref，不呼叫 live provider。

v1 schema files／舊錄製原始 bytes／output hash 不改、不補 time_range_source。新測試中的三份 v1 synthetic API recording 由合併產品 c1d9cbd 原生產出（Q1／Q2／Q3各一），以固定 file hash 驗證讀回完全相同。v1 的 API recorded playback 可獨立於新 parser 重播，不把新 parser 重算冒稱歷史產出。

portable source export 同步納入 time_source、reasons、stdlib schema validator 與 schema JSON，避免新 API 在封裝內缺依賴。未重建任何現有 LOCAL P1 包。

前端／kit 仍由 Claude owner 對接：PARSED structured_query.schema_version 顯示的是實際可執行 request，不是通用 intent 欄位；null 不推測。前端須傳 parse_response_ref 並顯示 DEFAULT_SELECTED_RUN；本 PR 不改前端或 kit。
